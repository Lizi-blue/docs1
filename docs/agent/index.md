# Agent 工程

这个方向按两条线组织。左线讲原理与协同，右线讲平台、入口与落地取舍。

## 学习路径

| 阶段 | 知识域 | 这一阶段回答什么 |
|---|---|---|
| 一 | 演进与定义 | 从基础问答到工具调用，agent 到底指什么 |
| 二 | 协同与并发 | 多 agent 怎么协作，并发与隔离怎么做 |
| 三 | 平台与工作台 | 平台能做什么、不能做什么 |
| 四 | 服务入口与权限 | 每个服务一个入口时，地址与权限怎么分 |
| 五 | 业界方案调研 | 业界常用项目怎么选，哪些只作参考 |
| 六 | 落地实践 | 写代码与维护集群时，agent 用在哪 |

## 术语表

| 术语 | 本方向的用法 |
|---|---|
| agent | 能在一轮任务里循环调用工具、并根据结果决定下一步的执行体 |
| 工具 | 交给模型调用的确定能力，有入参、有返回值、可能失败 |
| 上下文 | 一次任务里模型能看到的信息集合 |
| 记忆 | 跨会话保留的信息，分为会话、服务与平台三层 |
| 协同 | 多个 agent 分工与交接的方式 |
| 并发 | 同时推进多个任务的手段与隔离边界 |
| 工作台 | 长周期专项交付的入口，适合持续沟通 |
| 服务入口 | 某个服务的运行时控制入口，按服务限定权限 |
| 爬坡 | 任务从简单到复杂逐步加难度的过程 |
| 终止条件 | 循环结束的判据，缺它就会失控 |
| 熔断 | 成本或失败率超限时主动停下 |
| 审批点 | 需要人确认才能继续的步骤 |
