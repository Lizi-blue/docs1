# AI 辅助开发（Vibe Coding）

这个方向只回答一件事：当 Agent 出代码的速度超过人能逐行审查的速度时，
用什么结构化的东西替代「逐行读」。答案是三层：分层对象协作图、从图派生的测试、以及能放进 CI 的确定性检查。

## 学习路径

| 顺序 | 讲 | 这一讲回答什么 |
|---|---|---|
| 一 | 分层命名体系 | 你的 L1–L4 对应业界哪套命名，能不能保留 |
| 二 | 测试类型与 UIT | 测试地图怎么分，哪些能从图派生 |
| 三 | 逆向图与 CI 门禁 | 程序化逆向图可信到什么程度，什么能硬门禁 |

## 一句话结论（先给判断，再给依据）

- **分层命名**：没有唯一的业界标准。DDD 四层、整洁架构、六边形、C4 各管一件事。
  自定义 L1–L4 可以保留，前提是标注清楚它对齐的是「抽象层级」而不是「职责分层」。
- **测试派生**：从图能派生的是**场景路径**，不能派生**参数取值**与**非功能需求**。
  UIT 不是标准术语，把它当作「用例交互测试」的自定义叫法更稳妥。
- **逆向图门禁**：import 依赖图适合做硬门禁。函数调用图与对象协作图只能做辅助信号，
  因为 Python 的动态特性会让静态分析必然失真。

## 术语表

| 术语 | 本方向的用法 |
|---|---|
| 分层对象协作图 | 用对象与调用关系表达一次业务协作的图。审查的最小单元 |
| 设计图 | 人工确认过的图。作为比对基线 |
| 逆向图 | 用程序脚本从源码静态分析出的图 |
| 硬门禁 | 不通过就阻断合并的检查 |
| 辅助信号 | 只提示、不阻断的检查结果 |
| 漂移 | 设计图与逆向图出现结构差异 |
| 场景路径 | 图中一条从入口到结果的执行路径。用来派生测试 |
