# Feature Specification: 技术面试备考文档引擎（docs-1）

**Feature Branch**: `001-docs-engine`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "新建 docs-1 仓，域名 docs1.minilab.uzibird.cn；实现声明式文档引擎：按规则在 docs/ 目录放 Markdown 与 _meta.yml，引擎自动解析为可导航文档网站（渐进式学习 + 组件查询两类场景，领域内容可扩展）；本次用 Python 多线程/多进程知识域做目录划分与内容示例效果验证，含 1 个组件页；参照 ci 仓与 python-vue 仓接入 CI 流水线并部署；写作遵循受控中文规则，图解用 Archify，质量检查用 ste-lint-zh。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 零配置新增知识领域（Priority: P1）

内容作者在 `docs/` 下新建一个领域目录，放入一份目录级元数据与至少一个知识点页面，重新构建后站点自动出现该领域的导航入口、知识域分组与页面，作者不需要修改任何引擎代码或站点配置。

**Why this priority**: 这是引擎的立身之本。领域清单未来会从 `backend` / `frontend` / `k8s` 扩到 `3d-printing`、`woodworking` 等『引擎设计时未知』的领域；若每加一个领域都要改配置，引擎就退化为一次性站点。该能力同时是全部其他能力的载体。

**Independent Test**: 造一个最小领域（1 份 `_meta.yml` + 1 个知识点页，≤3 个文件），构建一次并检查产物；把该次变更与引擎/配置文件对比，后者改动数必须为 0。

**Acceptance Scenarios**:

1. **Given** 站点已可构建，**When** 在 `docs/` 下新增含目录级元数据与 1 个知识点页的领域目录并构建，**Then** 导航出现该领域，侧边栏出现其知识域与知识点，页面可通过稳定 URL 访问。
2. **Given** 目录或文件名带 `01-`、`02-` 数字前缀，**When** 渲染导航与页面，**Then** 排序由前缀决定，页面 URL 去掉前缀。
3. **Given** 新增领域从未在任何配置文件登记，**When** 提交并构建，**Then** 变更文件中引擎代码与站点配置文件数为 0。

---

### User Story 2 - 按学习路径逐步学习一个知识点（Priority: P1）

读者打开一个知识点页面，自上而下经过『原理讲解 → API 手册 → 组合用法 → 完整 Demo』四段，顶部能看到学习进度与前置知识，底部能看到关联知识点与关联组件，并能直接复制面试话术与代码。

**Why this priority**: 知识点页是内容主体，也是『面试备考』这一用户价值的直接兑现。四段式是内容契约，缺段即内容不合格。

**Independent Test**: 打开任一知识点页，逐项核对四段式必需小节、顶部进度与前置知识提示、底部关联链接，并执行一次页面内代码示例。

**Acceptance Scenarios**:

1. **Given** 一个知识点页，**When** 渲染，**Then** 四段式必需小节齐全：第一段含 TL;DR、概念定义、原理图解、关键对比；第二段含参数表、方法列表与折叠的最小示例；第三段含依赖知识点清单、数据流图解、分步实现与对比表；第四段含场景描述、完整代码、运行方式、追问链与关联组件。
2. **Given** 页面元数据声明了前置知识，**When** 读者打开页面，**Then** 顶部显示学习进度与前置知识提示，且前置知识可点击跳转到对应页面。
3. **Given** 页面元数据声明了关联知识点与关联组件，**When** 渲染，**Then** 页面底部自动生成双向关联链接。
4. **Given** 页面嵌入了原理图解，**When** 读者与其交互（点击/悬停/路径高亮），**Then** 图形有可见反馈，且断网状态下仍可交互（资源自包含）。
5. **Given** 页面元数据声明了层级与标签，**When** 渲染，**Then** 层级与标签在页面与索引中一致呈现，排序遵循声明顺序。

---

### User Story 3 - 按组件查询可复用方案（Priority: P2）

读者在组件页查看一个可复用组件由哪些知识点组合而成、完整源码是什么、其他项目如何引用，并一键复制安装命令。

**Why this priority**: 第二类使用场景。组件页把『知识点』变成『可搬走的资产』，是文档站区别于普通笔记站的价值点。

**Independent Test**: 打开组件页，核对双栏布局、安装命令复制、知识点对照表、完整源码与至少三种引用方式。

**Acceptance Scenarios**:

1. **Given** 一个组件页，**When** 渲染，**Then** 页面为双栏：左栏为简介、涉及知识点、组合方式图解与核心源码；右栏为引用方式。
2. **Given** 组件页顶部有安装命令，**When** 读者点击复制，**Then** 命令完整进入剪贴板。
3. **Given** 组件页声明了依赖知识点，**When** 渲染，**Then** 出现『知识点 | 对应学习页面 | 在本组件中的作用』对照表，且链接可达。
4. **Given** 组件页，**When** 读者阅读引用方式，**Then** 至少给出三种：包管理器安装、直接复制源码、在具体框架中集成。
5. **Given** 组件页，**When** 渲染，**Then** 展示组合方式图解与『与其他组件的关系』。

---

### User Story 4 - 推送即上线到 docs1.minilab.uzibird.cn（Priority: P2）

作者把内容或引擎改动推到主干，流水线自动构建站点镜像并部署到集群，读者随后通过 `https://docs1.minilab.uzibird.cn` 访问到本次改动。

**Why this priority**: 没有自动部署，文档站就无法持续演进；这也是本仓与中心仓 `ci`、母板仓 `python-vue` 的标准接入方式。

**独立测试**: 向主干推一次内容改动，观察流水线 Run 与站点首页内容是否同步更新。

**Acceptance Scenarios**:

1. **Given** 仓内已有薄触发工作流与仓内能力开关文件，**When** 推送到主干分支，**Then** 本仓 Actions 页出现自己的 Run，编排复用中心仓共享工作流，仓内不存在编排实现的副本。
2. **Given** 一次 Run，**When** 构建与部署阶段依次执行，**Then** 部署后站点健康检查返回成功，`https://docs1.minilab.uzibird.cn/` 返回 200 且内容包含本次提交的页面。
3. **Given** 打出 `vX.Y.Z` 版本标签，**When** 触发流水线，**Then** 额外产出带版本号与 `latest` 标签的镜像，并按发布逻辑部署到发布环境。
4. **Given** 推送发生在非部署分支，**When** 流水线执行，**Then** 只做构建与检查，不产生部署。
5. **Given** 流水线任一阶段失败，**When** 作者查看 Run 日志，**Then** 能定位到具体阶段与首个错误原因。
6. **Given** 站点已部署，**When** 检查集群内工作负载，**Then** 工作负载无后端服务、无数据库、无持久卷依赖，单副本可重建。

### User Story 5 - 受控中文写作机械门禁（Priority: P3）

内容作者在提交前对 `docs/**/*.md` 跑一次中文写作检查，得到可执行的修改清单；CI 中同一检查作为显式阶段运行，不静默跳过。

**Why this priority**: 写作风格靠人记必然漂移；机械门禁是让『一句话一动作、去掉套话』这类规则可持续的唯一手段。它依赖内容已存在，故优先级低于内容与部署。

**Independent Test**: 对一个合规文件与一个违规文件分别执行检查，比较退出码与输出清单。

**Acceptance Scenarios**:

1. **Given** 一个受控中文检查脚本，**When** 对 `docs/**/*.md` 执行，**Then** 输出通过/不通过结论与逐条问题（文件、行号、规则、修法）。
2. **Given** 检查不通过，**When** 流水线运行，**Then** Run 给出显式红灯或可修复清单，不得静默跳过、不得假绿。
3. **Given** 文档中的代码块、命令、专有名词与 API 名称，**When** 检查执行，**Then** 这些内容被豁免，不产生误报。

---

### Edge Cases

- 目录缺 `_meta.yml`、页面缺 frontmatter 或 `type`：构建给出可定位的告警并使用安全默认值，不中断整站构建。
- 同层出现重复数字前缀或缺前缀：排序稳定（按名称回退），并在构建输出中提示。
- 前置知识、关联知识点、关联组件指向不存在的页面：链接检查判红并指出来源文件与目标路径。
- 图解文件缺失或被引用但未生成：构建给出告警，页面显示『图解待补』占位，不出现空白区域。
- 图解 HTML 体积过大或含外部网络依赖：判定为不合格（必须自包含、可离线交互）。
- 新增领域名使用了与既有领域相同的目录名或与保留路径冲突：构建给出明确冲突原因。
- 中文门禁命中大量既有内容：允许一次性基线记录，但新增或修改文件的违规必须清零，基线只减不增。
- 域名解析或证书未就绪：部署仍可完成（Ingress 按 Host 路由），通过带 Host 头的请求验证站点，域名生效后无需改动仓库。

## Requirements *(mandatory)*

### Functional Requirements

**内容模型与元数据**

- **FR-001**: 内容 MUST 以仓库内的 Markdown 文件与 YAML 元数据为唯一事实源；站点 MUST NOT 依赖运行时数据库、后端服务或手工维护的导航清单。
- **FR-002**: 目录级元数据 MUST 支持声明领域知识域的名称、图标、顺序、描述、入口类型与学习路径（起点、终点、路径标签）；页面级元数据 MUST 支持声明标题、页面类型、所属领域、所属知识域、顺序、层级、标签、描述、前置知识、关联知识点、来源模块/API、关联组件、依赖知识点/组件、组件类型、安装命令、可复用度。
- **FR-003**: 目录与文件名 MUST 支持 `NN-` 数字前缀排序；去掉前缀后的名称 MUST 作为 URL 片段，且 URL 在同一领域内稳定。
- **FR-004**: 元数据缺失或非法时，解析 MUST 回退到安全默认值并输出可定位的告警，MUST NOT 中断整站构建。
- **FR-005**: 学习路径与知识域 MUST 由目录结构 + 目录级元数据推导，MUST NOT 由人工维护的导航清单定义。

**解析与导航**

- **FR-006**: 解析层 MUST 递归扫描 `docs/` 下的 Markdown 与目录级元数据，合并为站点索引（领域 → 知识域 → 知识点/组件），并以可被页面与导航消费的形式暴露。
- **FR-007**: 侧边栏 MUST 按『领域 → 知识域 → 知识点』三层自动生成；组件 MUST 支持按标签聚合的索引视图。
- **FR-008**: 站点 MUST 提供全站搜索，搜索索引 MUST 在构建阶段生成，无需运行时服务。
- **FR-009**: 新增领域 MUST 只需创建目录与文件；引擎代码与站点配置文件 MUST NOT 需要改动（零配置扩展）。
- **FR-010**: 引擎 MUST 通过自动化检查证明零配置扩展成立（在隔离的新增领域样本上断言导航与页面出现，且配置改动为 0）。

**页面契约**

- **FR-011**: 页面类型 MUST 至少覆盖 `knowledge`（知识点）、`component`（组件）、`cross-component`（跨领域组件）三类，且类型 MUST 决定布局；新增页面类型 MUST NOT 需要改动既有页面内容。
- **FR-012**: 知识点页 MUST 提供四段式结构：原理讲解（TL;DR、概念定义、原理图解、关键对比）、API 手册（参数表、方法列表、最小示例折叠）、组合用法（依赖知识点、数据流图解、分步实现、对比表）、完整 Demo（场景描述、完整代码、运行方式、面试追问链、关联组件）。
- **FR-013**: 知识点页 MUST 在顶部呈现学习进度与前置知识提示，并 MUST 在底部自动生成关联知识点与关联组件的双向链接。
- **FR-014**: 组件页 MUST 为双栏布局，包含简介、涉及知识点对照表、组合方式图解、核心源码，以及至少三种引用方式（包管理器安装、直接复制源码、框架内集成），并在顶部提供可复制的安装命令。
- **FR-015**: 跨领域组件 MUST 支持依赖汇聚展示（后端与前端知识点如何汇入同一组件），其源码展示 MUST 能体现前后端协作；本轮不提供该类型的示例内容。
- **FR-016**: 页面 MUST 提供可复用的渲染组件：进度条、前置知识提示、API 表格、安装命令框、代码标签页。
- **FR-017**: 站点内部链接 MUST 全部可达；构建阶段 MUST 校验内部链接并在断链时给出文件与目标定位。

**图解**

- **FR-018**: 原理图解、流程图、时序图、状态机图、依赖关系图 MUST 以自包含的交互 HTML 形式交付，存放于站点静态资源目录，并由知识点页/组件页嵌入。
- **FR-019**: 图解产物 MUST 可重复生成：保留可编辑的源描述（结构化数据）与生成步骤，二者入库；CI MUST NOT 依赖外网生成图解。
- **FR-020**: 图解 MUST 支持离线交互（点击、悬停、路径高亮），MUST NOT 依赖外部 CDN 或在线服务。
- **FR-021**: 云架构类静态专题图 MUST 支持在构建前由脚本生成图片并嵌入页面（可选能力，按需启用）。

**质量门禁**

- **FR-022**: 仓库 MUST 提供受控中文检查脚本，对 `docs/**/*.md` 输出结论与逐条问题（文件、行号、规则、修法），并支持代码块、命令与专有名词豁免。
- **FR-023**: 检查 MUST 作为流水线中的显式阶段运行；不通过时 MUST 判红或输出可修复清单，MUST NOT 静默跳过。
- **FR-024**: 仓库 MUST 提供写作规范文件（`AGENTS.md`），逐条列出受控中文规则与机械检查命令。
- **FR-025**: 仓库 MUST 提供 README，说明如何新增领域、新增知识点、新增组件（含每类操作的最少步骤与验收命令）。

**交付与部署**

- **FR-026**: 站点 MUST 以静态产物镜像交付：镜像内只含构建产物与静态服务器，无后端进程、无数据库、无持久卷依赖。
- **FR-027**: 部署 MUST 走中心仓 `ci` 流水线：仓内只保留薄触发工作流、能力开关文件、Dockerfile 与业务自带 K8s 清单，MUST NOT 复制中心仓编排实现。
- **FR-028**: 推送主干 MUST 自动构建镜像并部署；打版本标签 MUST 走发布逻辑（版本号 + `latest` 镜像标签）。
- **FR-029**: 部署 MUST 暴露 `docs1.minilab.uzibird.cn` 的 HTTPS 入口与健康检查端点；健康检查 MUST 在不依赖后端的情况下返回成功。
- **FR-030**: 部署 MUST 幂等且可回滚：重复部署不产生冲突，回滚到上一版本不依赖数据迁移。
- **FR-031**: 流水线 MUST 在站点内容层面可验证：部署后能断言线上页面包含本次提交的页面或内容标记。

**示例内容（本轮范围）**

- **FR-032**: `docs/backend/learn/01-concurrency/` MUST 提供 3 个知识点页：多线程基础、多进程基础、Queue 通信；三者 MUST 互为前置/关联且四段式完整。
- **FR-033**: `docs/backend/components/safe-queue.md` MUST 提供 1 个组件页，依赖上述知识点，并含完整源码与三种引用方式。
- **FR-034**: Python 并发示例 MUST 作为『目录划分 + 知识域划分 + 页面内容』三重效果验证：领域/知识域/学习路径由目录与元数据表达，不额外写导航代码。

### Key Entities

- **领域（domain）**：一个独立的技术方向（如 Python 后端）。由顶层目录 + 目录级元数据表达，带名称、图标、顺序、描述与知识域集合。
- **知识域（knowledge domain）**：领域内的一个主题分组（如并发编程），含名称、顺序、图标、描述与前置领域。
- **知识点页（knowledge page）**：教学单元，带层级、标签、来源模块、API 清单、前置知识与关联关系，内容遵循四段式。
- **组件页（component page）**：可复用资产，带组件类型、安装命令、依赖知识点、可复用度与引用方式。
- **跨领域组件页（cross-component page）**：依赖多个领域的组件，按领域聚合依赖。
- **学习路径（path）**：知识域内的推荐阅读次序，由目录级元数据声明起止与标签。
- **图解产物（diagram artifact）**：由结构化源描述生成的交互 HTML，随页面嵌入。
- **站点索引（doc tree）**：解析层产出的派生视图，驱动导航、侧边栏、搜索与关联链接；不手工维护。
- **内容变更（change）**：一次推送的 Markdown/元数据改动，是部署后验证的断言对象。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新增一个领域（≤3 个文件：目录级元数据 + 至少 1 页）后，一次构建即出现在导航与侧边栏；该次变更中引擎代码与站点配置文件改动数为 0。
- **SC-002**: 已交付的知识点页 100% 含四段式全部必需小节（缺失项计数为 0，可由自动化检查给出证据）。
- **SC-003**: 已交付的组件页 100% 含可复制安装命令、核心源码、知识对照表与 ≥3 种引用方式。
- **SC-004**: 站点内部链接断链数为 0。
- **SC-005**: 主干推送后 10 分钟内，`https://docs1.minilab.uzibird.cn/` 返回成功，且线上内容包含本次提交的页面（可用内容标记断言）。
- **SC-006**: `docs/**/*.md` 的中文写作检查 100% 通过；存在不可修复项时，输出清单条目可逐条定位到文件与行号。
- **SC-007**: 每个知识点页至少 1 个图解，且图解在断网环境下仍可交互（无外部资源请求）。
- **SC-008**: 内容作者新增一个知识点页的操作步骤 ≤3 步（建文件、写元数据、写正文），过程中无需改配置或引擎代码。
- **SC-009**: 首屏在常规内网条件下 3 秒内可读；站点静态资源总量不超过 20 MB（含图解）。
- **SC-010**: 流水线失败时，Run 日志首个错误可在 1 分钟内定位到阶段与原因（无『静默跳过』阶段）。

## Assumptions
