# Implementation Plan: Agent 方向（演进、原理、平台与落地实践）

**Branch**: `009-agent-domain` | **Date**: 2026-10-18 | **Spec**: [spec.md](./spec.md)

## Summary

把「业界现状 + 用户的想法」整理成一个**新方向**：`agent`。按既有方向（后端 Python 域）的格式与逻辑产出
领域 → 知识域 → 讲 的三级内容，覆盖演进主线、原理（定义／最小实现／协同／并发）、平台能力与局限、
两条使用路线（专项工作台／外部系统接入）、多服务入口与权限、业界方案调研与落地实践。

本仓是**文档与可行性研究仓**：不修改任何项目代码、不部署服务。本专题产出只有 Markdown 与自包含图解，
外加一条**公开安全门禁**（因为本仓同步到公开代码托管平台）。

## Technical Context

**内容形态**：静态站点内容（Markdown + 数据驱动元数据），非应用程序
**站点引擎**：既有 VitePress 构建（Node 运行时），本专题**不引入新依赖**
**领域注册**：数据驱动（领域目录下的元数据文件），新增领域不改站点配置（宪法 II）
**组织层级**：领域 → 知识域 → 讲；导航层级到三级（宪法 X）
**调研取数**：原生 HTTPS 取公开数据（代码托管平台接口、官方文档、发布说明），逐条标注抓取日期
**发布面**：静态内容同步到公开代码托管平台的 Pages；内容按**公开发布标准**书写
**门禁**：现有 13 条本地门禁 + **新增 1 条公开安全门禁**（扫描新增内容与仓内公开面）
**规模**：6 个知识域 / 18 讲 / 6 张自包含图解（草案见 spec 附录）
**未知项**：公开镜像的实际可见范围（整仓还是仅站点产物）→ 由 Phase 0 R3 决策并给待验证项

## Complexity Tracking

| 复杂度来源 | 为什么需要 | 简单替代为何不够 |

| 新增公开安全门禁 | 本仓同步到公开托管平台；现有门禁只扫站点产物与组件页，覆盖不到规格、schema 与根文件的示例值 | 只靠人工检查：新内容与既有文件都会长期漂移，无法防止回归 |
