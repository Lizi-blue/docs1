# 验收手册：Agent 方向

> 全部步骤可在本机执行；涉及站点点名时不写具体域名，统一称「内部站点」与「公开站点」。

## 前置

- 仓库已安装依赖，Node 与 Python 可用。
- 本专题不新增运行时依赖；不部署服务。

## 场景 1：结构与格式同构

```bash
npm run check:content      # 内容契约（含官方依据、层级）
npm run check:zh           # 受控中文
npm run check:nav          # 导航层级
```

**预期**：三条命令退出码 0；新增领域出现在导航，层级到 `1.1.1`；抽查 3 讲与基准方向结构一致。

## 场景 2：构建站点

```bash
npm run build
```

**预期**：构建成功；产物包含新增领域的页面与图解引用。

## 场景 3：公开安全扫描

```bash
npm run check:public-safety   # 新增门禁（实现阶段落地）
```

**预期**：新增内容与仓内公开面 0 命中；若历史文件命中，按契约替换为占位符后再提交。

## 场景 4：调研条目可核验

抽取 3 条调研条目，逐条核对：

1. 链接公开可访问；
2. 许可证、最近提交、是否归档齐备；
3. 标注了抓取日期与来源。

**预期**：3/3 通过；无来源数字 0 处。

## 场景 5：图解自包含

```bash
grep -R "https\?://" docs/public/diagrams/<新增图解>.html | grep -v "w3.org" | head
```

**预期**：除矢量命名空间与字体许可注释外，无外部资源加载地址。

## 场景 6：发布抽查

- 公开站点：打开新领域首页、任一讲与任一图解，均返回成功且无内网链接。
- 内部站点：同一批页面同样可访问。

**预期**：抽查页面全部成功；无死链。

## 场景 7：范围自检

```bash
git status --short
```

**预期**：只有 `docs/agent/**`、`diagrams/src/**`、`docs/public/diagrams/**`、规格文件与门禁脚本发生变化；
`service/` 与组件源码**零改动**（本专题不产出代码）。
