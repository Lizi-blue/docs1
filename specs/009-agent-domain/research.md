# Phase 0 调研决策：Agent 方向

> 每项给出决策、理由与被否方案。所有取数只走公开来源；涉及内部信息的一律抽象化。

## R1 调研数据怎么取

**决策**：用**原生 HTTPS** 直接取公开接口与官方文档（代码托管平台 API、项目发布说明、官方文档站）。

**理由**：本会话已验证可用——2026-10-18 用公开接口取到候选项目的星标数、许可证与最近提交时间；
不依赖付费检索服务，构建期也不联网（数据在写作时抓取并标注日期）。

**被否方案**：① 付费检索服务（额度受限，不可复现）；② 靠记忆写数字（无法核验，违反 FR-037）。

## R2 活跃度用什么口径

**决策**：最近提交时间 + 是否归档 + 许可证 三项为主，星标数只作参考；每条标注抓取日期。

**理由**：这三项能稳定拿到、含义明确、读者可自行复核；星标易受营销影响。

**被否方案**：拉取 issue/PR 活跃度与贡献者数量——口径不统一、易误读，留作人工抽查。

## R3 公开面边界与仓内既有泄漏怎么处理

**决策**：新增**公开安全门禁**扫描两类对象——①本次新增内容；②仓内公开面的示例值（文档、规格、schema、根文件）。
禁词覆盖：内网域名、私有地址段、内网主机名、内网仓库路径、凭据模式。**运维必需文件**（流水线配置、部署清单、
环境变量文件）不进入公开镜像，或改为占位符后再公开。

**理由**：规划期审计发现**10 个已跟踪文件**含内网域名或主机（根文件、文档、schema 示例、流水线与部署清单）。
本仓同步公开托管平台，这属于真实暴露面，光靠「新内容注意」覆盖不到历史文件。

**待验证**：公开镜像的实际可见范围（整仓 or 仅站点产物）。验证结果决定脱敏力度：
若整仓公开，则历史文件必须一并脱敏；若只公开站点产物，则保留运维文件原样、仅扫内容与产物。

**被否方案**：只扫站点产物——本次审计已证明历史文件里有命中，覆盖不足。

## R4 格式同构以哪里为基准

**决策**：以后端 Python 方向（`docs/backend/learn/**`）为格式基准：讲的四段式、教学要素、官方依据与追问链、
元数据字段与目录层级全部对齐。

**理由**：该方向已通过全部门禁，是仓内成熟样板；对齐它可复用引擎与门禁，无需新机制。

**被否方案**：另设一套 agent 专用格式——会产生第二套契约与门禁分支，违背零配置与单一事实源。

## R5 图解怎么产

**决策**：复用仓内既有离线图解工具链（源为 JSON，产物为自包含 HTML），规划 6 张：演进时间线、最小 agent 循环、
协同拓扑、并发隔离、入口架构、三层记忆归属。

**理由**：工具链已在仓内可用，产物自包含可入库，静态站直接引用；不需要联网。

**被否方案**：外链图片或在线渲染——违反自包含要求，公网读者也可能加载不到。

## R6 术语表放哪

**决策**：术语表作为**领域首页的一个小节**（可锚点跳转），并纳入门禁检查（术语必须出现且用词一致）。

**理由**：领域首页是读者第一落点；独立成页会与导航层级契约冲突。

**被否方案**：散落在各讲——同一术语多处定义必然漂移。

## R7 规模与篇幅

**决策**：6 知识域 / 18 讲；每讲四段式齐全、官方依据 ≥2 条；单讲聚焦一个可面试的问题，控制篇幅。

**理由**：与既有方向的粒度一致；便于分批交付（先 A/B 原理，再 C/D 平台与入口，再 E 调研、F 实践）。

**被否方案**：一次写 30+ 讲——交付周期过长，中间态难以验收。

## R8 未开写的知识域怎么登记

**决策**：以「大纲态」登记（元数据里标状态），**不建空页面**，与既有门禁一致；待内容开写再扩。

**理由**：避免空页被搜索引擎与读者当作正式内容；也避免门禁为占位内容放行。

## R9 本专题是否产出代码

**决策**：**不产出**。除新增一条门禁脚本外，不新增任何源码、不改被调研项目、不部署服务。

**理由**：用户明确本仓用于文档与可行性研究；这也解释了宪法 XI 的偏离（见 plan 的 Complexity Tracking）。

**被否方案**：顺手实现一个入口组件——超出授权范围，且会把研究结论与实现细节混在一起。
