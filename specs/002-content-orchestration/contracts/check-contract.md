# Contract: 校验契约（内容门禁 + 独立自检）

适用对象：门禁脚本维护者、内容作者、评审者。分工来自澄清决策 Q1：
**内容是否合规**走内容门禁并 fail-closed；**技能自身是否健康**走独立自检。

## 1. 两条命令

```bash
npm run check:content        # 内容门禁（含本特性新增的 V15–V18）
npm run check:orchestration  # 独立自检（S1–S7，技能与台账）
```

| 项 | 内容门禁 | 独立自检 |
|---|---|---|
| 退出码 | `0` 通过 · `1` 有错误 · `2` 脚本异常 | 同左 |
| 阻断构建 | 是（CI 中 fail-closed） | 否（评审与提交前运行；CI 可选） |
| 检查对象 | `docs/**` | `.dsh/skills/docs-authoring/**` 与 `ledger/**` |
| 人类输出 | `❌ [V<编号>] <文件>:<行> <问题> → 修法：<建议>` | `❌ [S<编号>] <问题> → 修法：<建议>` |
| JSON 输出 | `--json`：`{ ok, errors: [{code,file,line,message,fix}], warnings, stats }` | `--json`：`{ ok, errors: [{code,message,fix,subject}] }` |

## 2. 内容门禁新增规则（接在 001 的 V1–V14 之后）

| 编号 | 检查 | 判据 | 失败输出 |
|---|---|---|---|
| V15 | 知识域 `teach` 块 | 存在且五字段齐全、类型正确（见 `schemas/teach-block.schema.json`） | 文件名 + 缺失字段 + 修法（给模板片段） |
| V16 | 四要素与链条目数 | `### 本讲要解决的问题`、`### 常见误区`、`### 面试追问链`、`### 下一讲衔接` 四个标题存在；`### 面试追问链` 节内 `<details>` 条目为 3–5 条 | 列缺失标题或实际条目数 |
| V17 | 登记与页面双向完整 | `teach.lessons[].slug` 归一化后与知识点页 url 双向一致 | 列出「幽灵条目」与「未登记页面」两份清单 |
| V18 | 要素内容非空 | 各要素标题下 ≥1 行实质文本；`### 常见误区` ≥1 条列表项；`### 下一讲衔接` 含至少一个页面链接 | 指出空要素名 |

**归属说明**：四要素的「存在性、条数、非空」属内容合规，故进内容门禁；
技能是否有重复取值、台账格式、导出指纹属技能自身健康，故进独立自检。两者 MUST NOT 重复实现同一判定。

## 3. 独立自检规则

| 编号 | 检查 | 判据 | 失败输出 |
|---|---|---|---|
| S1 | 技能内取值零复制 | 技能正文 MUST NOT 出现内容契约的取值型片段：字段名清单（如 `component_type`、`tags_index` 等成组出现 ≥3 个）、阈值数字（如 `40 字`、`25 字`、`3–5 条`、`≤12 讲`）、目录树结构块 | 列出疑似片段的位置与行号，并提示改为指针 |
| S2 | 技能章节齐全且有序 | 九个必需章节按 `skill-contract.md` §2 的顺序出现 | 列出缺失或错序的章节 |
| S3 | 台账格式与连续三次规则 | 表头逐字一致、列数一致、`decision` 与 `review` 取值合法；连续三条 `no-writeback` 后无 `recheck:*` 即判错 | 行号 + 缺失的复核记录说明 |
| S4 | 指针可达 | 技能内所有指向仓内文件的链接/路径均存在 | 列出失效指针 |
| S5 | 导出指纹一致 | 导出物存在时，其 `body-sha256-16` 等于当前源导出区的指纹；不存在则跳过并提示 | 提示「源已变更，请重新导出」 |
| S6 | 技能版本与变更日志一致 | `.dsh/skills/docs-authoring/SKILL.md` 首部版本号 MUST 等于同目录 `CHANGELOG.md` 最新条目的版本，且最新条目日期 MUST 不早于正文最后修改日期 | 指出两处版本号与两处日期，提示「改技能请同时递增版本与补条目」 |
| S7 | 中文门禁基线只减不增 | 从台账 `reason` 列取最近一条 `baseline:<N>`，与 `scripts/ste-lint-zh.baseline` 的当前值比对；当前值更大即判错。改动基线 MUST 在 `reason` 写 `baseline:<N>` | 打印两次数值，提示「补复核记录，或把基线回落到 `<N>`」 |

**S1 边界**：判定对象是内容契约的取值型片段（页面 frontmatter 字段名、阈值数、目录树结构块）。
`skill-contract.md` §5 强制要求「可直接复制」的模板代码块不参与判定，判据本体中的 `≤12 讲`、
`3–5 条`、`≥2 条` 同样保留。

**S4 边界**：判定对象是以 `specs/`、`docs/`、`.specify/`、`.dsh/` 开头的完整仓内相对路径
与 Markdown 链接。含 `<` 或 `*` 的占位路径、目录约定名与字段名不参与判定。

**S6/S7 边界**：两者只读，MUST NOT 改写技能正文、变更日志或基线文件。基线文件不存在时，
S7 判错并提示「先建立 `scripts/ste-lint-zh.baseline`」。

## 4. 夹具负例（实现时必须能红）

| 夹具 | 期望 |
|---|---|
| 删掉某知识域 `teach.audience` | V15 判错，输出字段名 |
| 删掉某页 `### 常见误区` | V16 判错，输出缺失标题 |
| 追问链改成 2 条 | V16 判错，输出「实际 2 条，需 3–5 条」 |
| `teach.lessons` 留一条指向不存在的 slug | V17 判错，列幽灵条目 |
| 新增一页但不登记 slug | V17 判错，列未登记页面 |
| `### 常见误区` 只有标题没有内容 | V18 判错 |
| 技能里贴一份字段清单 | S1 判错，列位置 |
| 打乱技能章节顺序 | S2 判错，列错序章节 |
| 台账连写三条 `no-writeback` | S3 判错，要求补复核记录 |
| 手改导出物一个字符 | S5 判错，提示重新导出 |

## 5. 与 001 门禁的关系

- V 编号 MUST 从 001 的 V14 之后继续，MUST NOT 重排既有编号。
- `npm run check:content` 是本特性与 001 共用的单一内容门禁入口，本特性 MUST NOT 新建第二个内容门禁。
- 独立自检在提交前与评审时运行；是否加入 CI 由 001 的 T029（Dockerfile 门禁序列）决定，
  加入时 MUST 作为独立步骤，不得与内容门禁合并成一次调用。
