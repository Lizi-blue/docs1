# Contract: 编排技能契约（skill）

适用对象：技能作者与评审者。技能是被 Agent 与作者共同消费的资产，结构一旦发布，
MUST NOT 在特例里临时增删章节；变更走 `CHANGELOG.md` 与版本号。

## 1. 落位与形态

| 项 | 约定 |
|---|---|
| 仓内路径 | `.dsh/skills/docs-authoring/SKILL.md`（宪法 VIII 指定） |
| 变更日志 | `.dsh/skills/docs-authoring/CHANGELOG.md` |
| 前置 | `.gitignore` MUST 把 `.dsh/` 收窄为 `.dsh/skills/speckit-*`，否则本技能无法入库 |
| 头部 | YAML frontmatter：`name: docs-authoring` + `description`（一句话说明何时加载） |
| 版本 | 正文首部写 `技能版本：x.y.z`，与 `CHANGELOG.md` 最新条目一致 |

## 2. 必需章节（顺序不可变，自检 S2 断言）

| # | 节标题 | 内容要求 |
|---|---|---|
| 1 | `## 何时加载` | 列出触发场景（新增领域/知识域/知识点/组件、调整学习路径、内容评审） |
| 2 | `## 目录落位与命名` | 目录层级、`NN-` 前缀、两个入口；只放规则，不复制字段清单 |
| 3 | `## 编排判据` | 四类判据，每类含可判定条件、一个正例、一个反例 |
| 4 | `## 每讲教学结构` | 四要素的标题、位置与写法要求 |
| 5 | `## 模板` | `teach` 块、知识点页骨架、组件页骨架、路径声明；可直接复制 |
| 6 | `## 工具选用` | 写作规则、交互图解（含图型表）、云架构静态图；各配反例与降级路径 |
| 7 | `## 常见错误与修法` | ≥5 条：错误现象 → 修法 |
| 8 | `## 自检与门禁` | 完整命令：内容门禁、中文门禁、独立自检、构建 |
| 9 | `## 优先级与变更日志` | 宪法 > 内容契约 > 本技能；指向 `CHANGELOG.md` |

## 3. 编排判据（第 3 节的必需内容）

| 判据 | 可判定条件 | 正例 | 反例 |
|---|---|---|---|
| 知识点拆分与合并 | 一个页面只回答一个「面试可问的问题」；两个问题若互相依赖且共用同一段代码，合并为一页；若可独立使用且示例不同，拆两页 | 「多线程基础」独立成页 | 把「线程」与「进程」合成一页，示例混杂 |
| 知识域划分 | 同一知识域内的页面共享一套术语与一个可运行环境；跨环境切换必须换域 | 「并发编程」内含线程/进程/队列/异步 | 把「并发编程」与「内存模型」合成一域 |
| 路径排法与长度 | 按依赖顺序排；单知识域 ≤12 讲；超过 12 讲时拆域或先分子主题 | 「线程 → 进程 → 队列 → 异步」 | 先讲 asyncio 再讲线程 |
| 组件与知识点对应 | 组件页依赖的知识点必须全部存在；一个组件至少依赖 2 个知识点 | `safe-queue` 依赖 Queue 与进程池 | 组件只依赖 1 个页面且没有新增组合价值 |

## 4. 每讲教学结构（第 4 节的必需内容）

| 要素 | 标题（逐字） | 位置 | 要求 |
|---|---|---|---|
| 本讲要解决的问题 | `### 本讲要解决的问题` | `## TL;DR` 之前 | 2–4 句，说明这页解决什么、为什么现在学 |
| 常见误区 | `### 常见误区` | `### 面试追问链` 之前 | ≥2 条列表项，每条含错误说法与纠正 |
| 面试追问链 | `### 面试追问链` | 第四段内 | `<details>` 条目 3–5 条，后一问依赖前一问结论 |
| 下一讲衔接 | `### 下一讲衔接` | `### 关联组件` 之前 | 一句话 + 至少一个指向下一讲的链接 |

## 5. 模板（第 5 节的必需内容）

### 5.1 `teach` 块模板

```yaml
teach:
  audience: "<目标读者，10–80 字>"
  prerequisites:
    - "<知识前提>"
  outcomes:
    - "<学完能做什么>"
  path:
    - from: "<起始页 slug>"
      to: "<结束页 slug>"
      label: "<分段标签>"
  lessons:
    - slug: "<页面 slug>"
      goal: "<这一讲要达成什么，10–60 字>"
```

### 5.2 知识点页骨架

```markdown
### 本讲要解决的问题
<2–4 句>
## TL;DR
> <2–3 句面试话术>
## 概念定义 … ## 原理图解 … ## 关键对比 …
## API 手册：<模块>
## 组合用法：<功能>
### 组合了哪些知识？ ### 数据流图解 ### 分步实现 ### 对比表格
## 完整 Demo：<场景>
### 场景描述 ### 完整代码 ### 运行方式
### 常见误区
### 面试追问链
### 下一讲衔接
### 关联组件
```

### 5.3 组件页骨架与路径声明

组件页骨架见 001 的 `contracts/content-contract.md` §5（本技能只给指针与填写顺序）；
路径声明即 5.1 的 `teach.path`。

## 6. 工具选用（第 6 节的必需内容）

### 6.1 写作规则检查

| 项 | 约定 |
|---|---|
| 何时用 | 每次提交前，对 `docs/**` 全量跑 |
| 命令 | `npm run check:zh`（内部调用 vendored 脚本） |
| 阈值 | 硬违规为 0；存量走基线，基线只减不增 |
| 局部停用 | 只允许 `--disable <规则>` 且写进提交信息 |
| 反例 | ① 在文件里写忽略标记绕过；② 为了让存量通过而放宽阈值；③ 自造一条「等价」规则替代上游规则 |

### 6.2 交互图解（Archify）

| 图要回答的问题 | 图型 |
|---|---|
| 有什么组件、边界在哪 | architecture |
| 谁调用谁、顺序如何 | sequence |
| 数据怎么流动 | dataflow |
| 状态怎么变化 | lifecycle |
| 有哪几步、谁来审批 | workflow |

| 项 | 约定 |
|---|---|
| 图注 | MUST 写明这张图回答的问题 |
| 放置 | MUST 在 `## 原理图解` 或 `### 数据流图解` 内 |
| 反例 | ① 把图当装饰散在正文；② 一个知识点用两张图回答同一个问题；③ 图里塞进图注未提的信息 |
| 降级 | 无法生成时手写自包含 HTML，记录在迭代台账的 `reason` 里 |

### 6.3 云架构与拓扑静态图

| 项 | 约定 |
|---|---|
| 何时用 | 讲云资源、网络拓扑、部署形态的专题页 |
| 反例 | ① 用静态图替代调用时序；② 在没有云架构专题的领域提前引入 |
| 降级 | 用表格描述拓扑，并标注「待补静态图」 |

## 7. 优先级与冲突

1. 与宪法冲突：以宪法为准，MUST 在技能内声明该优先级。
2. 与内容契约冲突：以契约为准，并开一条任务改技能（MUST NOT 两处各改一半）。
3. 变更 MUST 记入 `CHANGELOG.md`（日期 / 改动 / 原因）并递增版本号。
