# Feature Specification: 内容编排与教学法技能（content-orchestration）

**Feature Branch**: `002-content-orchestration`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: 「持续总结改进一份内容编排划分 skill，优化渐进式学习的教学方式；文档内容要求合理使用 asd-ste100-skill-zh、archify、diagrams」（承宪法 v1.1.0 新增原则 VIII；本条承接上一步 `/speckit-constitution` 里列为待办的「建内容编排技能」意图）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 作者按统一编排落地一个新知识域（Priority: P1）

内容作者（人，或加载了该技能的 Agent）要新增一个学习方向或知识域。技能给出可判定的划分判据、
路径排法、每讲的教学结构，以及可直接套用的模板与登记表。作者照着产出，不需要凭个人经验决定
「一个知识点该不该独立成页」「路径该多长」「这一讲该讲什么」。

**Why this priority**: 这是技能存在的第一理由。没有统一编排，内容量一涨就是各写各的，
渐进式学习退化为文件堆。

**Independent Test**: 让一位未读过本仓历史的作者，仅凭技能，在规定时间内产出一个符合内容契约的
知识点页与一份知识域登记表。

**Acceptance Scenarios**:

1. **Given** 技能已可加载，**When** 作者新增一个知识域，**Then** 技能给出：该域的目标读者、先修、
   学完能做什么、路径分段与每讲教学目标，并有可直接填写的登记表模板。
2. **Given** 作者要判断某主题是否独立成页，**When** 阅读编排判据，**Then** 判据给出可判定的条件与
   正反例，作者能在不超过一次提问的情况下做出决定。
3. **Given** 作者新建一个知识点页，**When** 套用技能模板，**Then** 产出页含四段式结构与四个教学要素，
   并通过内容机械校验。
4. **Given** 一个知识域只有一个知识点，**When** 套用判据，**Then** 判据允许单页知识域，不强迫凑数。

---

### User Story 2 - 读者获得稳定的学习节奏（Priority: P1）

读者沿路径学习时，每一讲的讲法一致：先知道这一讲要解决什么问题，再看到常见误区，学完能回答
面试追问链，并知道下一讲接什么。路径本身有明确起点与先修关系。

**Why this priority**: 教学效果来自节奏一致。每讲结构不同，读者就要重新适应一次。

**Independent Test**: 抽查任意三讲，核对四要素是否齐备、追问链是否递进、与下一讲是否有衔接。

**Acceptance Scenarios**:

1. **Given** 任意知识点页，**When** 读者打开，**Then** 能看到本讲要解决的问题、常见误区、
   面试追问链、与下一讲的衔接四项内容。
2. **Given** 一个知识域，**When** 读者进入入口页，**Then** 能看到路径分段、推荐起点与每讲的层级。
3. **Given** 读者学完一个知识域，**When** 进入组件查询，**Then** 能看到该知识域的知识点被哪些组件复用。

---

### User Story 3 - 每次内容迭代回写技能（Priority: P2）

每次内容迭代（新增或修改页面、调整路径）都要判定是否回写技能，并留下记录。技能带变更日志，
逐条记录日期、改了什么、为什么。连续多次声明「无需回写」会触发复核。

**Why this priority**: 「持续总结改进」的落点是可追溯的变更记录。没有记录，改进只停在口号。

**Independent Test**: 检查最近三次内容迭代的提交与技能变更日志，确认每条都有回写或「无需回写」判定。

**Acceptance Scenarios**:

1. **Given** 一次内容迭代，**When** 作者收尾，**Then** 技能变更日志或迭代记录里出现一条判定
   （回写条目，或「本次无需回写」及理由）。
2. **Given** 连续三次判定为无需回写，**When** 评审介入，**Then** 复核记录里给出「判据仍有效」或
   「判据需更新」的结论。
3. **Given** 技能发生变更，**When** 评审查看日志，**Then** 每条变更都含日期、内容与原因三要素。

---

### User Story 4 - 技能可跨仓复用（Priority: P2）

技能有两处形态：本仓内一份供 Agent 直接加载，另一份上架到组织技能仓供其他仓复用。
两处只有判据与指针，取值只存在一份。

**Why this priority**: 未来会有多个文档仓；编排经验沉淀一次、复用多处，才谈得上持续改进。

**Independent Test**: 在另一个仓加载跨仓技能，确认能拿到完整判据与模板，且修改判据只需改一处。

**Acceptance Scenarios**:

1. **Given** 跨仓技能已上架，**When** 其他仓加载它，**Then** 能获得判据、模板与自检入口，
   并通过指针回溯到规范正文。
2. **Given** 判据需要修改，**When** 作者改动，**Then** 只需改一处，另一处仍可正确回溯。
3. **Given** 两处技能内容，**When** 运行自检，**Then** 能检出重复取值与两处描述冲突。

---

### User Story 5 - 三类工具的选用判据与反例（Priority: P3）

技能写清三类内容工具的分工与选用判据：写作规则的机械检查、交互图解（含图型选择）、
云架构静态专题图。每一类都给出「什么时候用」「不要这样做」的反例。

**Why this priority**: 工具本身不是难点，用错场景才是。判据与反例能挡住大多数误用。

**Independent Test**: 抽查五张图解与五段正文，核对是否都符合技能给出的选用判据。

**Acceptance Scenarios**:

1. **Given** 一张待画的图，**When** 作者按判据选择图型，**Then** 图型与该图要回答的问题一致，
   且图注写明该问题。
2. **Given** 一段正文，**When** 作者运行写作规则检查，**Then** 规则来源唯一，检查结果可定位到行。
3. **Given** 一个云架构专题，**When** 作者选择工具，**Then** 走静态专题图路径；非云架构场景
   MUST NOT 使用该工具。
4. **Given** 工具不可用的环境（例如未安装图解生成工具），**When** 作者继续写作，**Then** 技能给出
   降级路径与记录方式，不阻塞其它内容产出。

---

### Edge Cases

- 技能与内容契约冲突：以契约为准，同时开一条任务改技能，MUST NOT 两处各改一半。
- 技能与宪法冲突：以宪法为准；技能 MUST 内声明该优先级。
- 一个知识域确实只容纳一个知识点：判据允许，MUST NOT 为凑数拆页或并页。
- 路径过长（单知识域超过 12 讲）：判据给出拆分建议与判断依据。
- 连续多次无需回写：触发复核，避免判据过期却无人发现。
- 两处技能漂移（仓内与跨仓版本不一致）：自检 MUST 能检出。
- 既有内容缺四要素：技能给出迁移清单，允许分批补齐并记录剩余量。
- 图解生成工具版本变化导致产物不一致：记录生成环境与版本，产物入库，CI 不联网重生成。

## Requirements *(mandatory)*

### Functional Requirements

**技能本体**

- **FR-001**: 仓库内 MUST 有一份可被 Agent 直接加载的编排技能，位置与命名 MUST 固定，加载后无需
  额外交付物即可工作。
- **FR-002**: 技能 MUST 覆盖四项编排判据：知识点的拆分与合并、知识域的划分、学习路径的排法与长度、
  组件与知识点的对应关系。
- **FR-003**: 每项判据 MUST 给出可判定的条件与至少一个正例与一个反例。
- **FR-004**: 技能 MUST 提供可直接套用的模板：知识域登记表、知识点页骨架、组件页骨架、
  学习路径声明。
- **FR-005**: 技能 MUST 说明常见错误与对应修法，至少覆盖：路径顺序错、知识域粒度过细或过粗、
  同一事实写两处、图与文重复。

**教学要素**

- **FR-006**: 每个知识点页面 MUST 含四个教学要素：本讲要解决的问题、常见误区、面试追问链、
  与下一讲的衔接。
- **FR-007**: 追问链 MUST 递进（后一问依赖前一问的结论），条目数在 3 到 5 之间。
- **FR-008**: 知识域入口 MUST 呈现路径分段、推荐起点与每讲的层级标注。
- **FR-009**: 教学要素 MUST 有机械判据（可校验的存在性与条数），MUST NOT 只靠人工印象。

**迭代与留痕**

- **FR-010**: 每次内容迭代 MUST 留下一条技能判定记录：回写条目，或「本次无需回写」及理由。
- **FR-011**: 技能 MUST 有变更日志，每条含日期、改动内容、原因。
- **FR-012**: 连续三次判定无需回写时，MUST 产生一条复核记录并给出结论（判据仍有效 / 需更新）。

**跨仓复用**

- **FR-013**: 技能 MUST 有跨仓形态，供其他文档仓复用；跨仓版本 MUST 通过指针回溯到本仓规范正文。
- **FR-014**: 两处技能 MUST 只放判据与指针；取值类内容（字段清单、目录约定、阈值）MUST 只存在一处。
- **FR-015**: 技能 MUST 提供自检入口，能检出：重复取值、两处描述冲突、内容缺四要素、路径声明缺项。

**工具分工**

- **FR-016**: 技能 MUST 给出写作规则检查的选用判据：规则来源唯一，检查结果可定位，豁免有唯一入口。
- **FR-017**: 技能 MUST 给出交互图解的选用判据与图型选择表，并要求图注写明该图回答的问题。
- **FR-018**: 技能 MUST 给出云架构静态专题图的适用边界，并明确非适用场景的替代做法。
- **FR-019**: 每类工具 MUST 配至少一条「不要这样做」的反例。
- **FR-020**: 工具不可用时 MUST 有降级路径与记录方式，MUST NOT 阻塞其它内容产出。

**与既有规范的关系**

- **FR-021**: 技能 MUST NOT 复制内容契约的取值，只允许指针与判据。
- **FR-022**: 技能 MUST 声明优先级：与宪法冲突以宪法为准，与内容契约冲突以契约为准。
- **FR-023**: 技能 MUST 覆盖新增领域与新增组件的编排路径，不只覆盖知识点。
- **FR-024**: 技能上线后 MUST 对既有知识点页做一次收口：补齐四个教学要素，并记录剩余未补量。

### Key Entities

- **编排技能（skill）**：本仓内的一份可加载文档，含判据、模板、反例、自检入口与优先级声明。
- **跨仓技能（shared skill）**：组织技能仓里的一份同源版本，只放判据与指针。
- **知识域登记表（registry entry）**：一个领域或知识域的编排声明：目标读者、先修、学完能做什么、
  路径分段、每讲教学目标。
- **教学要素（teaching element）**：每讲必须包含的四项内容（问题、误区、追问链、衔接）。
- **变更日志条目（changelog entry）**：日期、改动内容、原因。
- **迭代判定记录（iteration decision）**：回写条目，或「无需回写」及理由；连续三次触发复核记录。
- **自检清单（self-check）**：检重复取值、两处冲突、缺四要素、路径缺项。
- **工具选用判据（tool guidance）**：三类工具的适用范围、选择表与反例。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未读过本仓历史的作者，凭技能在 30 分钟内产出一个通过机械校验的知识点页。
- **SC-002**: 评审按技能判据核查一页，用时不超过 5 分钟，并给出可定位到小节与行的结论。
- **SC-003**: 自检入口对全部既有知识点页运行后，缺四要素的页面可枚举；收口完成后缺失数为 0。
- **SC-004**: 最近三次内容迭代中，含技能变更或判定记录的比例为 100%。
- **SC-005**: 技能内取值重复数为 0（只允许指针）。
- **SC-006**: 新增一个知识域（含登记表与首讲）从开始到通过校验的时间不超过 60 分钟。
- **SC-007**: 跨仓技能加载后，其他仓无需阅读本仓规范正文即可获得完整判据；判据修改只改一处。
- **SC-008**: 抽查 5 张图解，图型与「图回答的问题」一致的比例为 100%，图注齐备比例为 100%。
- **SC-009**: 追问链条目数在 3 到 5 之间的知识点页比例为 100%，且链条递进（评审抽查 3 页无断链）。

## Assumptions

- **技能位置**：仓内为项目技能目录下的一份技能文档（宪法 VIII 指定的形式），跨仓为组织技能仓中的
  同源版本；两处都是文档资产，不是代码。
- **本轮范围**：交付技能正文、模板、自检入口、变更日志、跨仓形态，并完成既有知识点页的四要素收口
  （作为技能的首次应用）。不新增第三类工具，不改造站点引擎。
- **前置改动**：当前仓库忽略整个项目技能目录（为避免重复的技能副本入库）。要让本技能入库，
  需把忽略规则收窄为只忽略第三方技能副本，这属实现改动，不在本规格内。
- **工具来源已定**：写作规则来自 `lemonhall/asd-ste100-skill-zh`；交互图解来自 Archify；
  云架构静态图来自 `mingrammer/diagrams`。三者均为用户指定的既有选型。
- **规则优先级**：宪法（v1.1.0，含原则 VIII）高于内容契约，内容契约高于本技能正文。
- **读者与语言**：技能面向中文内容作者与 Agent，正文中文，代码与命令保留英文。
- **规模预期**：技能需在 10 个领域、1000 个页面的规模下仍可执行判据，故判据必须可机械核对。
