# 契约：GitHub Pages 流水线（pages-workflow-contract）

适用对象：`.github/workflows/pages.yml`。判据来源：`spec.md` 的 FR-001、FR-005、FR-006、FR-008、FR-009、FR-013。

## 1. 触发

| 项 | 约定 |
|---|---|
| 事件 | 推送到主分支；并保留手动触发入口 |
| 路径 | 不设路径过滤：内容与引擎变更都可能影响产物 |
| 与内网关系 | 两条流水线各自触发，MUST NOT 互相等待或共享运行状态 |

## 2. 权限与环境

| 项 | 约定 |
|---|---|
| 权限 | `contents: read`、`pages: write`、`id-token: write`；其余权限 MUST NOT 申请 |
| 环境 | 绑定 `github-pages` 环境，使发布记录可追溯 |
| 并发 | 按分支分组并开启「取消进行中的旧运行」，保证最终发布对应最新提交 |
| 超时 | MUST 设置合理上限（建议 ≤ 15 分钟），避免卡死的运行长期占用 |

## 3. 步骤顺序（缺一不可，顺序固定）

1. 检出代码。
2. 准备运行时：安装站点依赖（锁定文件，可缓存）。
3. 准备门禁运行时：Python 与测试框架（公共源安装）。
4. 执行**与内网侧同一套门禁**（内容、中文、编排、组件测试、门禁自测、零配置、构建、响应式、导航、组件页、体验）。
5. 以**公网基础路径**构建站点。
6. 生成公网产物附加件：`.nojekyll` 与深链兜底页。
7. 执行**产物门禁**：基础路径前缀、内网地址零泄漏、外部资源零引用、兜底页存在。
8. 配置 Pages → 上传产物 → 部署。

## 4. 失败策略

| 场景 | 行为 |
|---|---|
| 任一门禁失败 | MUST NOT 上传或部署；日志指出失败步骤；上一版本继续可用 |
| 产物门禁失败 | 同上，并列出命中的内网地址或未加前缀的链接样本 |
| 平台配置未就绪（Pages 未开启） | MUST 给出可操作提示（指出需要开启的开关），MUST NOT 只报通用错误 |
| 部署阶段失败 | MUST 保留完整日志与产物为可下载件，便于定位 |

## 5. 可观测

- 运行记录 MUST 能对应到提交（页面可见提交短哈希）。
- 成功后 MUST 暴露页面地址（环境输出或运行摘要）。
- 失败 MUST 能定位到具体步骤（步骤名可读，不使用汇总步骤掩盖）。

## 6. 禁止事项

- MUST NOT 依赖内网地址、本机集群、私有包源或私有镜像源。
- MUST NOT 使用长期凭据；发布使用平台托管的短期身份。
- MUST NOT 把后端服务打进公网发布（Pages 只托管静态产物）。
- MUST NOT 修改内网流水线、清单或站点容器配置。
