# Feature Specification: 组件面向对象重构与教学专题（oo-component-teaching）

**Feature Branch**: `008-oo-component-teaching`

**Created**: 2026-10-13

**Status**: Draft

**Input**: User description: 「后端任务控制台组件中依赖的知识域与知识点与下面的涉及的知识点是什么关系是否重复？写的内容基本一致，要求：组件这块必须以面向对象形式开发，讲解时分别讲解每个对象 然后对象之间如何调用 流程如何等等 这样也方便画类似 archify diagram 的图。将该要求写入宪法。重构所有组件内容。」

**先答用户提问**：两节**重复**。「依赖的知识域与知识点」由 frontmatter 渲染，「涉及的知识点」是手写表格，
两处列的是同一批知识点与同样的作用说明（后端页均为 4 条：任务编排与线程池、子进程与信号、同步原语与死锁、套接字与流）。
本专题 MUST 删掉其中一处，知识点只在一处登记（FR-014）。

**宪法状态**：原则 XII「组件以对象建模并逐对象讲解（NON-NEGOTIABLE）」已写入，宪法升到 **1.6.0**。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 先给对象模型，再讲实现（Priority: P1）

读者打开组件页，先看到一张对象清单：有哪些对象、各自负责什么、持有什么。
看完清单就知道这个组件的骨架，而不是先读一堆按功能排列的代码。

**Why this priority**: 对象模型是讲解与图解的共同骨架，也是后续三节的前提。

**Independent Test**: 打开任一组件页，确认「对象模型」小节存在，且包含对象清单表（对象 | 职责 | 状态 | 生命周期）。

**Acceptance Scenarios**:

1. **Given** 任一组件页，**When** 打开，**Then** 在核心源码之前出现对象模型小节。
2. **Given** 对象清单，**When** 阅读，**Then** 每个对象都有职责、状态与生命周期三列。
3. **Given** 清单，**When** 对照源码，**Then** 每个对象在源码中都有对应的类或模块单元。

### User Story 2 - 每个对象单独成节（Priority: P1）

每个对象都有自己的一节：它负责什么、持有什么、暴露哪些方法与属性、边界在哪。
读者可以只读某一节，就能理解这个对象。

**Why this priority**: 用户明确要求「分别讲解每个对象」。

**Independent Test**: 抽查两个对象小节，确认每节都有职责、状态、方法、边界四部分，且方法名与源码一致。

**Acceptance Scenarios**:

1. **Given** 组件页，**When** 数对象小节，**Then** 小节数与对象清单条数一致（≥3）。
2. **Given** 对象小节，**When** 阅读，**Then** 能看到职责、持有、方法、边界四项。
3. **Given** 方法名，**When** 对照源码，**Then** 名称与签名一致。

### User Story 3 - 对象之间如何调用、流程怎么走（Priority: P1）

读者能看到对象之间的持有与调用关系，以及关键流程怎么走：正常路径、失败路径与取消路径。
流程用编号步骤写清「谁调用谁、传什么、返回什么」。

**Why this priority**: 用户明确要求讲「对象之间如何调用、流程如何」。

**Independent Test**: 抽查一条关键流程，确认步骤≥5、每步标注调用方与被调方，且包含至少一条失败路径。

**Acceptance Scenarios**:

1. **Given** 组件页，**When** 找到对象关系小节，**Then** 关系用「持有 / 调用 / 回调」三类标注。
2. **Given** 关键流程，**When** 阅读步骤，**Then** 每步写明调用方、被调方与数据形态。
3. **Given** 失败路径，**When** 阅读，**Then** 写明异常如何传播与资源如何释放。

### User Story 4 - 图解对应对象模型（Priority: P2）

图解不再只是流程图：至少一张对象关系图与一张关键流程时序图，节点名与对象名一致。

**Why this priority**: 用户要求「方便画类似 Archify diagram 的图」，图必须与对象模型同名同构。

**Independent Test**: 打开图解，确认节点名全部出现在对象清单中，且时序图步骤与流程小节编号一致。

**Acceptance Scenarios**:

1. **Given** 组件页，**When** 打开图解，**Then** 存在对象关系图与时序图各一张。
2. **Given** 图解节点，**When** 对照对象清单，**Then** 名称一一对应，无临时命名。
3. **Given** 时序图，**When** 对照流程小节，**Then** 步骤顺序一致。

### User Story 5 - 知识点只登记一处（Priority: P2）

组件页不再重复列知识点：删掉手写表格，保留由 frontmatter 渲染的索引，读者只在一处看到依赖关系。

**Why this priority**: 用户发现两节内容基本一致，重复会让人怀疑哪份才是准的。

**Independent Test**: 打开组件页，确认只有一节知识点章节，且其数据来自 frontmatter。

**Acceptance Scenarios**:

1. **Given** 任一组件页，**When** 统计知识点章节，**Then** 数量为 1。
2. **Given** 该章节，**When** 修改 frontmatter，**Then** 页面内容随之变化（单一事实源）。
3. **Given** 组件页契约与门禁，**When** 运行，**Then** 已按新章节表校验。

## Requirements *(mandatory)*

### Functional Requirements

**对象建模**

- **FR-001**: 组件页 MUST 在实现细节之前给出对象模型小节。
- **FR-002**: 对象模型 MUST 含对象清单表：对象、职责、状态、生命周期。
- **FR-003**: 每个对象 MUST 单独成节，含职责、持有关系、暴露的方法与属性、边界。
- **FR-004**: 组件源码 MUST 以对象为单位组织；MUST NOT 把逻辑堆进单个过程式脚本。
- **FR-005**: 对象名 MUST 在三处一致：对象清单、对象小节标题、源码类名。
- **FR-006**: API 手册 MUST 按对象分组，方法组名 MUST 与对象名一致。

**协作与流程**

- **FR-007**: 组件页 MUST 给出对象关系小节，标注持有、调用与回调。
- **FR-008**: 组件页 MUST 给出至少两条关键流程，每条步骤 ≥5，写明调用方、被调方与数据形态。
- **FR-009**: 流程 MUST 覆盖失败路径与取消路径，并写明资源释放时机。
- **FR-010**: 对象生命周期 MUST 写明创建者、销毁时机与资源归属。

**图解**

- **FR-011**: 组件页 MUST 含对象关系图与关键流程时序图各至少一张。
- **FR-012**: 图解节点名 MUST 与对象清单一致，MUST NOT 出现临时命名。
- **FR-013**: 图解 MUST 自包含，MUST NOT 引用外部网络资源。

**单一事实源**

- **FR-014**: 知识点 MUST 只登记一处；MUST 删除手写表格一节。
- **FR-015**: 组件页契约章节表 MUST 同步更新，门禁 MUST 按新章节表校验。
- **FR-016**: 宪法原则 XII MUST 已写入并生效（已完成，版本 1.6.0）。

**对象层级与关系（用户补充要求）**

- **FR-017**: 组件页 MUST 展示对象层级：父类、子类，以及子类扩展或覆盖的方法。
- **FR-018**: 对象之间存在继承时，MUST 给出继承关系图；继承边 MUST 可与组合边区分。
- **FR-019**: 组合关系（谁持有谁）MUST 与继承关系分开标注，MUST NOT 混为一类。
- **FR-020**: 层级图与对象清单 MUST 同名同构，MUST NOT 出现清单外的类名。

### Key Entities

- **ObjectModel**：对象模型；对象清单、职责、状态、生命周期。
- **ObjectCard**：对象卡；职责、持有、方法、属性、边界。
- **Collaboration**：对象协作；关系类型（持有／调用／回调）、触发条件、数据形态。
- **Sequence**：流程时序；名称、步骤列表、失败分支、资源释放点。
- **DiagramBinding**：图解绑定；图类型、节点集合、与对象模型的对应关系。
- **KnowledgeIndexEntry**：知识点登记；页面、作用、所属知识域（唯一登记处）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三个组件页（进程安全队列、后端任务服务、前端控制台）每页对象数 ≥3，且都有对象清单表。
- **SC-002**: 每页对象小节数等于清单条数，比例 100%。
- **SC-003**: 每页至少 2 条关键流程，每条步骤 ≥5，含失败路径。
- **SC-004**: 每页对象关系图与时序图各 ≥1 张，节点名与对象清单一致率 100%。
- **SC-005**: 知识点章节每页 1 处，重复章节数 0。
- **SC-006**: 源码按对象组织：每个对象在源码中有独立单元（类或模块），无「单脚本堆逻辑」。
- **SC-007**: 十三条门禁全绿（含按新章节表校验的组件页门禁）。
- **SC-008**: 内网与公网发布成功，抽查三个组件页正常。
- **SC-009**: 宪法版本为 1.6.0 且含原则 XII。
- **SC-010**: 后端任务服务的三组真实继承在页面与图中均有对应：
  `TaskHandler(BaseHTTPRequestHandler)`、`TaskServer(ThreadingHTTPServer)`、`ValidationError(ValueError)`。
- **SC-011**: 门禁对「源码存在继承但页面缺继承小节」判错；继承表中的子类名全部能在源码中找到。

## Assumptions

- 本专题**允许修改组件页正文**（用户明确要求重构组件内容），但不改 URL 与导航层级。
- 组件源码可在本仓内重构为对象结构（后端服务模块、前端单文件组件、队列组件均适用）。
- 删除「涉及的知识点」一节后，组件页章节表由 16 节变为 15 节，契约与门禁需同步。
- 图解继续走 Archify 流程，产物自包含。

## 附：三个组件的对象清单草案（供重构与画图使用）

> 草案用于对齐对象边界；实现阶段以源码实际结构为准，逐项核对后再定稿。

### 1. 进程安全队列（`/backend/components/safe-queue`）

| 对象 | 职责 | 状态 | 生命周期 |
|---|---|---|---|
| `SafeQueue` | 组装队列与 worker，对外提供投递与收取 | worker 列表、任务队列 | 由调用方 `with` 创建与关闭 |
| `Worker` | 从队列取任务、执行、把结果放进结果队列 | 进程身份、当前任务 | 随 `SafeQueue` 启动；收到哨兵退出 |
| `Task` | 承载一个待执行单元与参数 | 函数、参数 | 投递时创建 |
| `TaskResult` | 承载成功值或异常信息 | ok、value、error | worker 执行后创建 |
| `Sentinel` | 通知 worker 退出的哨兵 | 无 | 关闭时按 worker 数投递 |

关键流程：投递 → 取任务 → 执行 → 回传结果 → 关闭（投哨兵 → 等待 → 释放）。

### 2. 后端任务服务（`/backend/components/task-console`）

| 对象 | 职责 | 状态 | 生命周期 |
|---|---|---|---|
| `Allowlist` | 命令白名单与参数校验 | 允许命令集合 | 进程启动时加载配置 |
| `TaskRegistry` | 任务状态机与查询 | 任务字典、锁 | 进程级单例 |
| `OutputBuffer` | 环形缓冲与截断标记 | 分片、序号、上限 | 随任务创建与销毁 |
| `StreamHub` | SSE 订阅与断线续传 | 订阅者集合、游标 | 进程级单例 |
| `Executor` | 线程池调度与并发名额 | 线程池、运行中计数 | 进程启动时创建，退出时关闭 |
| `ChildProcess` | 每任务子进程与进程组 | pid、pgid、信号状态 | 任务开始时创建，结束时回收 |
| `MetricsSampler` | 采样 CPU 与内存 | 采样快照 | 随任务运行期间周期性执行 |

关键流程：下发 → 校验 → 入队 → 取名额 → 起子进程 → 采集输出 → 推送 → 结束/取消 → 回收。

### 3. 前端任务控制台（`/frontend/components/task-console`）

| 对象 | 职责 | 状态 | 生命周期 |
|---|---|---|---|
| `ApiClient` | 四个端点的请求与错误映射 | base 地址 | 组件挂载时创建 |
| `EventStream` | SSE 连接、续传与去重 | 连接、游标、重连次数 | 订阅时创建，结束时关闭 |
| `TaskStore` | 任务列表与状态机 | 任务列表、选中项 | 组件级响应式状态 |
| `CommandForm` | 命令与参数录入与校验 | 输入值、校验结果 | 组件级状态 |
| `LogView` | 输出渲染、自动滚动与截断提示 | 行集合、滚动位置 | 组件挂载时创建 |
| `Notice` | 提示与降级文案 | 级别、文案 | 随事件创建与清除 |

关键流程：提交 → 创建任务 → 建立订阅 → 追加输出 → 完成/取消 → 关闭订阅。
