# 参考其他 VitePress 主题的版式做法（保留本仓自研引擎）

**结论先说**：本仓**不整体更换主题**。原因是自研引擎与门禁深度耦合：
`doc-engine`（元数据 → 页面树 → 虚拟模块）、`cmp-split`（组件页双栏）、12 个主题组件、
9 条内容门禁与 13 条机械门禁都直接依赖当前类名与 DOM 结构。
整体换主题会同时改动类名、DOM 与门禁判据，代价高且容易再次出现「规则通过但界面破版」。

**改为「借版式度量」**：把成熟主题里被反复验证的**尺寸与节奏**搬进本仓令牌层，
结构与引擎保持自研。下面是与本仓相关的通用做法（主题名仅作来源标注）。

## 1. 常见的版式度量（社区主题普遍采用）

| 度量 | 常见取值 | 本仓令牌 | 说明 |
|---|---|---|---|
| 整页布局上限 | 1440–1600px | `--docs1-layout-max: 1600px`（映射 `--vp-layout-max-width`） | 宽屏利用率 |
| 文档区上限 | 1100–1280px | `--docs1-doc-max: 78rem` | 正文 + 侧栏 |
| 正文阅读栏 | 44–50rem | `--docs1-content-measure: 46rem` | 约 65–75 字符 |
| 左栏宽度 | 240–300px | VitePress 默认 | 不自行改写 |
| 右栏宽度 | 200–240px | VitePress 默认 | 空目录时自动收起 |
| 顶栏高度 | 60–64px | `--docs1-nav-height: 64px` | 单行 |
| 间距节奏 | 4/8/12/16/24/32 | `--docs1-space-0…9` | 已有 |
| 圆角阶梯 | 4/8/12 | `--docs1-radius-sm/md/lg` | 已有 |
| 宽内容外扩 | 正文栏 ±3–4rem | `--docs1-bleed: 6rem`（**仅主栏**） | 代码/表格可越界 |

## 2. 从主题做法里学到的四条工程习惯

1. **右栏必须有内容才占位**：容器空时收起（本仓用 `:has(.VPDocOutlineItem:empty)`），
   而不是让空列白占 224px。
2. **父级容器要先放开**：只改内层 `max-width` 无效——VitePress 的 `.container` / `.content`
   自身有上限，必须一起放宽。
3. **组件自带分栏的页面不要叠加框架右栏**：否则同页出现 4 个竖列，正文只剩 20% 多。
4. **`markdown.headers` 必须显式开启**：否则 `headersPlugin` 不注册，页面目录全站为空。

## 3. 若将来确要整体换主题（PoC 路径，不动现有两档）

1. 新增第三个档位 `DOCS1_LAYOUT=<theme>`，与 `taste` / `classic` 并列。
2. 在分支上引入主题，只改 `theme/index.ts` 与 `Layout.vue` 的装配，不动 `docs/**` 内容。
3. 门禁适配清单：`check:responsive`、`check:experience`、`check:layout` 的类名判据需按新主题重写。
4. 用 `audit-layout` 量取与现档同口径对比（重叠、正文宽度、利用率），达到或超过才切换。

（本文件不代为保证）。本仓当前为零第三方运行时依赖。
