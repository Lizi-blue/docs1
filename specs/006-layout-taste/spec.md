# Feature Specification: 参照 taste-skill 优化布局、目录与内容布局（layout-taste）

**Feature Branch**: `006-layout-taste`

**Created**: 2026-10-13

**Status**: Draft

**Input**: User description: 「参考 github taste-skill 95k star 的那个项目，专门优化一下我们的布局，目录，和页面内容的布局。要求能随时恢复到现有样式。」

**参照实现**：[Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill)（95,033 ★，MIT）。
适用条目与文档场景适配见 [reference/taste-skill-digest.md](./reference/taste-skill-digest.md)。

**Design Read**：技术文档站，受众为准备中高级面试的开发者，以桌面长文阅读为主；
既有基线已有设计令牌与十二条机械门禁，导航层级到 `1.1.1`。
档位取 `DESIGN_VARIANCE 5 / MOTION_INTENSITY 3 / VISUAL_DENSITY 3`（文档场景，非营销站默认值）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 改造随时可回滚（Priority: P1）

在本轮视觉与版式改造中，任何一步都能回到改造前的样子。回滚不需要重建标签、不需要手工比对文件，
一条命令即可，且回滚后全部门禁仍然通过。

**Why this priority**: 这是用户显式提出的硬约束，也是所有后续改造的安全前提。没有它，改造不可逆。

**Independent Test**: 在任意改造完成后的提交上执行恢复命令的预演，确认待恢复文件清单正确；
执行恢复后跑十二条门禁，确认全绿且页面版式与基线一致。

**Acceptance Scenarios**:

1. **Given** 改造已进行若干提交，**When** 执行恢复命令的预演，**Then** 输出待恢复的布局文件清单，且不修改工作区。
2. **Given** 执行恢复，**When** 运行十二条门禁，**Then** 全部通过，页面版式与基线一致。
3. **Given** 站点已按优化后布局发布，**When** 使用运行时的经典样式切换，**Then** 无需重新部署即可回到经典样式，且刷新后保持该选择。
4. **Given** 构建时选择经典布局，**When** 与优化后布局分别构建，**Then** 两次构建都成功，产物互不污染。

### User Story 2 - 布局更专业（Priority: P1）

页面骨架更接近专业文档站：整页限宽居中、栏位比例稳定、导航单行且不侵占阅读区、首屏就能看到主要入口。
读者在 375 / 768 / 1280 三档宽度下都不会遇到横向滚动或错位。

**Why this priority**: 「布局」是用户点名的第一项；骨架问题会同时拉低目录与正文的观感。

**Independent Test**: 抽查 5 个代表页面（领域首页、学习入口、知识点页、组件页、组件索引），
量取顶栏高度、整页容器宽度、首屏主要入口是否可见，并在三档宽度确认无横向溢出。

**Acceptance Scenarios**:

1. **Given** 桌面宽度 1280，**When** 打开任一页，**Then** 顶栏单行且高度不超过 80px。
2. **Given** 桌面宽度 1280，**When** 打开领域首页，**Then** 标题与主要入口在首屏内可见（无需滚动）。
3. **Given** 375 / 768 / 1280 三档宽度，**When** 浏览抽查页面，**Then** 无横向溢出，宽内容在自身容器内滚动。
4. **Given** 任一多列区块，**When** 窄屏折叠，**Then** 折叠形态在该区块内声明，不依赖框架默认行为。

### User Story 3 - 目录更好用（Priority: P1）

导航与页内目录承载到 `1.1.1` 的层级但不显拥挤：层级靠缩进与密度表达，当前项有明确选中态，
窄桌面下压缩标签而不是换行，页内目录能定位长文的每一节。

**Why this priority**: 「目录」是用户点名的第二项；本仓导航已到三级层级，密度与选中态是关键。

**Independent Test**: 在知识点页与组件页上逐级展开导航，确认三级层级可见、当前项高亮、键盘焦点可见；
在 1024 宽度确认顶栏不换行；页内目录条目与正文标题一一对应。

**Acceptance Scenarios**:

1. **Given** 1024 宽度，**When** 展开顶栏下拉，**Then** 内容不换行，标签被压缩而非折行。
2. **Given** 侧栏三级层级，**When** 浏览，**Then** 层级用缩进与密度区分，当前项有明确选中态与可见焦点。
3. **Given** 长知识点页，**When** 使用页内目录，**Then** 条目覆盖正文各级标题，点击准确跳转。
4. **Given** 任一页，**When** 统计章节小标签，**Then** 数量不超过区块数的三分之一。

### User Story 4 - 内容布局更好读（Priority: P1）

正文、代码、表格、图框与卡片使用同一套语言：标题阶差清晰、行宽落在可读区间、
长文留白而数据手册加密、明暗主题取值一致。

**Why this priority**: 「页面内容的布局」是用户点名的第三项；它决定实际阅读体验。

**Independent Test**: 抽查 3 个知识点页量取正文行宽（65–75 字符区间）与标题阶差；
抽查 API 手册页确认表格密度与滚动；切换深色主题确认同语义同值。

**Acceptance Scenarios**:

1. **Given** 任一知识点页，**When** 量取正文列宽，**Then** 落在大约 65–75 字符的可读区间。
2. **Given** API 手册页，**When** 窄屏浏览，**Then** 宽表格在自身容器内滚动，不撑破版面。
3. **Given** 深色主题，**When** 对比同一语义元素，**Then** 取值一致且可读。
4. **Given** 同一页面，**When** 盘点版式家族，**Then** 同一家族不重复出现超过一次。

### User Story 5 - 门禁与既有约定不退化（Priority: P2）

改造不降低质量门槛：十二条门禁继续通过，且把新的布局规则做成可机械判定的断言，
避免后续改动把版式问题带回来。

**Why this priority**: 宪法 III/IV 要求规则可执行；不可判定的规则会随时间失效。

**Independent Test**: 运行十二条门禁与新增布局断言，全部通过；故意破坏一条布局规则确认会被判错。

**Acceptance Scenarios**:

1. **Given** 优化后布局，**When** 运行十二条门禁，**Then** 全部通过。
2. **Given** 新增布局断言，**When** 人为引入断点缺失或版式重复，**Then** 断言判错并指出位置。
3. **Given** 两端发布链路，**When** 推送，**Then** 内网与公网均发布成功，页面正常。

## Requirements *(mandatory)*

### Functional Requirements

**可回滚（安全前提）**

- **FR-001**: 改造前的布局状态 MUST 以注解标签形式存在于远端仓库，标签内容 MUST 覆盖全部布局相关文件。
- **FR-002**: MUST 提供一条恢复命令，能按名恢复到基线布局；命令 MUST 支持预演模式且预演 MUST NOT 修改工作区。
- **FR-003**: MUST 提供构建期开关选择「经典布局」或「优化后布局」，默认取优化后；取值非法时 MUST 报错并终止构建。
- **FR-004**: MUST 提供运行时的经典样式切换入口，切换 MUST NOT 需要重新部署，且选择 MUST 在后续访问中保持。
- **FR-005**: 经典样式 MUST 原样保留（MUST NOT 边改边删）；改造 MUST NOT 改变内容、URL 与导航层级。

**布局面**

- **FR-006**: 断点 MUST 标准化为 640 / 768 / 1024 / 1280 / 1536。
- **FR-007**: 整页容器 MUST 限宽居中；多列布局 MUST 使用网格，MUST NOT 用百分比算术模拟栅格。
- **FR-008**: 桌面端顶栏 MUST 单行，高度 MUST 不超过 80px。
- **FR-009**: 领域首页与学习入口的首屏 MUST 容纳标题与主要入口动作。
- **FR-010**: 每个多列区块 MUST 在同一处声明窄屏折叠形态。

**目录面**

- **FR-011**: 侧栏 MUST 用缩进与密度表达三级层级，MUST NOT 依赖多重分隔线。
- **FR-012**: 导航当前项 MUST 有明确选中态，键盘焦点 MUST 可见。
- **FR-013**: 窄桌面下导航 MUST 压缩标签或收纳次级项，MUST NOT 换行。
- **FR-014**: 章节头 MUST NOT 使用「左大标题 + 右小说明」的分裂式结构。
- **FR-015**: 章节小标签 MUST 节制：每 3 个区块最多 1 个。
- **FR-016**: 页内目录 MUST 覆盖正文各级标题并可准确跳转。

**内容布局面**

- **FR-017**: 正文列宽 MUST 落在约 65–75 字符的可读区间；标题阶梯 MUST 走设计令牌。
- **FR-018**: 卡片、图框、代码块与表格 MUST 使用统一的圆角、描边与阴影语言。
- **FR-019**: 内容密度 MUST 分级：长文留白，API 手册与数据表加密。
- **FR-020**: 同一页面内同一版式家族 MUST NOT 重复超过一次。
- **FR-021**: 明暗主题下同一语义 MUST 取同一令牌值；交互元素 MUST 覆盖默认、悬停、焦点、按下、禁用与加载。
- **FR-022**: 全站 MUST 尊重减少动效偏好，动画 MUST NOT 驱动布局属性。

**门禁**

- **FR-023**: 既有十二条门禁 MUST 继续通过。
- **FR-024**: 新增布局断言 MUST 进 CI，覆盖断点标准、顶栏单行与高度上限、版式家族重复、小标签计数、正文行宽。

### Key Entities

- **LayoutProfile**：布局档位；取值 `classic` / `taste`，含来源（构建期开关或运行时选择）与默认值。
- **BaselineSnapshot**：基线快照；标签名、覆盖文件清单、恢复命令与预演结果。
- **LayoutRule**：可机械判定的布局规则；编号、判据、判定方式（机械或人工）与证据位置。
- **SurfaceMap**：三个改造面（布局、目录、内容布局）与各自落点文件的映射。
- **RouteInvariant**：内容与路由不变量；URL、导航层级与内容契约在改造前后必须一致。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 恢复命令（含预演）在 1 分钟内完成，恢复后十二条门禁全部通过。
- **SC-002**: 两种构建期取值都能构建成功，产物互不污染；运行时切换无需重新部署，刷新后保持选择。
- **SC-003**: 抽查 5 个页面：桌面顶栏单行且高度 ≤80px；领域首页与学习入口首屏可见主要入口。
- **SC-004**: 375 / 768 / 1280 三档宽度抽查无横向溢出，响应式门禁通过。
- **SC-005**: 抽查 5 个页面的版式家族：单页同族出现次数 ≤1。
- **SC-006**: 抽查 3 个长页：小标签数量 ≤ ⌈区块数 ÷ 3⌉。
- **SC-007**: 抽查 3 个知识点页：正文行宽落在 65–75 字符区间。
- **SC-008**: 十二条门禁 + 新增布局断言全绿；故意破坏一条布局规则时断言判错并给出位置。
- **SC-009**: 内网与公网两条发布链路在改造后均发布成功，抽查页面正常。

## Assumptions

- 参照项目为 `Leonxlnx/taste-skill`（95,033 ★，MIT）；只借鉴其规则，MUST NOT 引入其代码依赖。
- 规则摘要与文档化适配落在 `specs/006-layout-taste/reference/taste-skill-digest.md`，供离线复核。
- 内容、URL 与导航层级保持不变（已发布链接与宪法 X 的稳定性要求）。
- 基线标签 `layout-baseline-pre-taste` 指向改造前提交；恢复不依赖重建标签。
- 维持零第三方运行时依赖，不引入 UI 组件库。
- 视觉观感与真实视口的最终确认由人工在浏览器完成；机械断言只守可判定部分。
