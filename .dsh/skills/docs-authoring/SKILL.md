## 何时加载

出现下列任一情况时加载本技能。

- 新增领域或调整领域边界。
- 新增知识域或调整知识域边界。
- 新增知识点页或删除知识点页。
- 新增组件页或变更组件页。
- 调整学习路径的顺序或分段。
- 评审已有内容的教学结构。
- 判定本次迭代是否需要回写本技能。

本技能给判据、模板与命令。字段取值以内容契约为准。

## 目录落位与命名

- 领域目录放 `docs/<domain>/`。
- 领域目录名可带 `NN-` 前缀。
- 每个领域根目录 MUST 同时有 `learn/` 与 `components/`。
- `learn/` 与 `components/` 各有一个 `index.md` 入口页。
- `learn/` 入口面向学习路径。
- `components/` 入口面向组件检索。
- 知识域是 `learn/` 下的一级目录。
- 知识点页放所属知识域目录内。
- 组件页放 `components/` 目录内。
- 跨领域组件目录见该契约 §1。
- `NN-` 前缀只用于排序。
- URL MUST NOT 带 `NN-` 前缀。
- 同一目录去前缀后同名即冲突。
- 目录深度上限与入口页约定见 `specs/001-docs-engine/contracts/content-contract.md` §1。
- 目录元数据字段与页面字段同样以该契约 §2 与 §3 为准。

## 编排判据

四类判据各给条件、正例与反例。

### 知识点拆分与合并

- 条件：一个页面只回答一个面试可问的问题。
- 条件：两个问题互相依赖且共用同一段代码，合并为一页。
- 条件：两个问题可独立使用且示例不同，拆成两页。
- 正例：「多线程基础」独立成页。
- 反例：把「线程」与「进程」合成一页，示例混杂。

### 知识域划分

- 条件：同一知识域内的页面共享一套术语。
- 条件：同一知识域内的页面共享一个可运行环境。
- 条件：跨环境切换必须换域。
- 正例：「并发编程」内含线程、进程、队列与异步。
- 反例：把「并发编程」与「内存模型」合成一域。

### 路径排法与长度

- 条件：路径按依赖顺序排。
- 条件：单知识域 ≤12 讲。
- 条件：超过 12 讲时先拆域。
- 条件：拆不动时先分子主题。
- 正例：「线程 → 进程 → 队列 → 异步」。
- 反例：先讲 asyncio 再讲线程。

### 组件与知识点对应

- 条件：组件页依赖的知识点 MUST 全部存在。
- 条件：一个组件至少依赖 2 个知识点。
- 正例：`safe-queue` 依赖队列与进程池。
- 反例：组件只依赖 1 个页面且没有新增组合价值。

## 每讲教学结构

四要素标题 MUST 逐字一致。位置与写法见下表。

| 要素 | 标题 | 位置 | 写法 |
|---|---|---|---|
| 本讲要解决的问题 | `### 本讲要解决的问题` | `## TL;DR` 之前 | 2–4 句。说明这页解决什么。说明为什么现在学。 |
| 常见误区 | `### 常见误区` | `### 面试追问链` 之前 | ≥2 条列表项。每条给错误说法与纠正。 |
| 面试追问链 | `### 面试追问链` | 第四段内 | `<details>` 条目 3–5 条。后一问依赖前一问结论。 |
| 下一讲衔接 | `### 下一讲衔接` | `### 关联组件` 之前 | 一句话加至少一个下一讲链接。末讲指向本域组件页或知识域入口，不留空。 |

## 模板

模板可直接复制。字段类型与取值上限以 schema 为准。

### teach 块

```yaml
teach:
  audience: "<目标读者>"
  prerequisites:
    - "<知识前提>"
  outcomes:
    - "<学完能做什么>"
  path:
    - from: "<起始页 slug>"
      to: "<结束页 slug>"
      label: "<分段标签>"
  lessons:
    - slug: "<页面 slug>"
      goal: "<这一讲要达成什么>"
```

字段定义见 `specs/002-content-orchestration/contracts/schemas/teach-block.schema.json`。

### 知识点页骨架

```markdown
### 本讲要解决的问题
<2–4 句>
## TL;DR
> <2–3 句面试话术>
## 概念定义 … ## 原理图解 … ## 关键对比 …
## API 手册：<模块>
## 组合用法：<功能>
### 组合了哪些知识？ ### 数据流图解 ### 分步实现 ### 对比表格
## 完整 Demo：<场景>
### 场景描述 ### 完整代码 ### 运行方式
### 常见误区
### 面试追问链
### 下一讲衔接
### 关联组件
```

四要素与段落的必需标题见 `specs/001-docs-engine/contracts/content-contract.md` §4。

### 组件页骨架

组件页结构以内容契约为准。本技能只给指针与填写顺序。

- 结构见 `specs/001-docs-engine/contracts/content-contract.md` §5。
- 先写组件简介与知识点对应表。
- 再写组合图解与核心源码。
- 然后写设计说明与使用文档。
- 最后写引用方式与组件间关系。
- 安装命令由页面字段渲染。作者只填值。

### 路径声明

- 路径声明写在知识域目录元数据的 `teach.path` 下。
- 每段给起止页 slug 与分段标签。
- 起止页 slug 可带或不带 `NN-` 前缀。
- 引擎读路径时回退到顶层 `path`。
- 迁移完成后 MUST 删除顶层 `path`。

## 工具选用

### 写作规则检查

- 提交前对 `docs/**` 与本技能正文运行 `npm run check:zh`。
- 规则正文与豁免见 `specs/001-docs-engine/contracts/content-contract.md` §7。
- 硬违规 MUST 为 0。存量违规走基线。
- 基线只减不增。改动基线 MUST 在台账 `reason` 列写 `baseline:<N>`。
- 局部停用只允许 `--disable <规则>`。
- 停用理由 MUST 写进提交信息。
- 反例一：在文件里写忽略标记绕过门禁。
- 反例二：为了让存量通过而放宽阈值。
- 反例三：自造一条等价规则替代上游规则。
- 降级：门禁脚本不可用时先人工检查受控中文。
- 降级 MUST 记进台账 `reason`，且 MUST NOT 长期保留。

判定流程见 `specs/002-content-orchestration/contracts/check-contract.md` §3。

### 交互图解

图型按「这张图要回答什么问题」选择。

| 图要回答的问题 | 图型 |
|---|---|
| 有什么组件、边界在哪 | architecture |
| 谁调用谁、顺序如何 | sequence |
| 数据怎么流动 | dataflow |
| 状态怎么变化 | lifecycle |
| 有哪几步、谁来审批 | workflow |

- 图注 MUST 写明这张图回答的问题。
- 图 MUST 放 `## 原理图解` 或 `### 数据流图解` 之内。
- 单页至少一张图。
- 图 MUST 离线可用。
- 图源与产物 MUST 入库。
- 反例一：把图当装饰散在正文。
- 反例二：一个知识点用两张图回答同一个问题。
- 反例三：图里塞进图注未提的信息。
- 降级一：工具不可用时手写自包含 HTML。
- 降级二：图缺失时先留占位并给构建告警。
- 降级原因 MUST 记进台账 `reason`。

### 云架构静态图

- 只用于云资源、网络拓扑与部署形态专题页。
- 图源 MUST 用 `.py` 描述并入库。
- 产物 MUST 在构建前生成并入库。
- MUST NOT 用它替代交互时序图。
- MUST NOT 在没有云架构专题的领域提前引入。
- 反例一：用静态图替代调用时序。
- 反例二：在没有云架构专题的领域提前引入。
- 反例三：只交图片不交 `.py` 源。
- 降级：用表格描述拓扑，并标注待补静态图。

## 常见错误与修法

| 现象 | 修法 |
|---|---|
| 一个页面塞进两个问题 | 拆成两页，各留一个示例。 |
| 页面只讲概念，没有运行入口 | 补完整 Demo 与运行方式。 |
| 追问链条目不足 | 补到 3–5 条，再检查依赖顺序。 |
| 常见误区只写标题 | 每条补错误说法与纠正。 |
| 知识点页漏登记到知识域 | 在 `teach.lessons` 补 slug 与目标。 |
| 组件依赖不存在的知识点 | 先补知识点页，再改依赖。 |
| 图没有图注 | 补一句话写明该图回答的问题。 |
| 路径顺序反了 | 按依赖顺序重排，再检查分段。 |
| 改了技能不同步版本 | 递增版本并补变更日志条目。 |
| 目录深度超出上限 | 拆知识域，或改用子主题。 |
| 图型与问题不匹配 | 按「图回答什么」重选图型。 |

## 自检与门禁

五条命令与适用时机如下。

| 命令 | 时机 | 作用 |
|---|---|---|
| `npm run check:content` | 提交前与 CI | 内容合规。判错即阻断构建。 |
| `npm run check:zh` | 提交前与 CI | 受控中文。硬违规 MUST 为 0。 |
| `npm run check:orchestration` | 提交前与评审 | 技能与台账健康。不阻断构建。 |
| `npm run export:skill` | 技能版本变更后 | 生成导出物并算指纹。 |
| `npm run build` | 提交前与 CI | 站点可构建。 |

### S6 版本一致

- 技能正文首部写版本号。
- 变更日志最新条目给同一个版本号。
- 最新条目日期 MUST 不早于正文最后变更日期。
- 改技能 MUST 同时递增版本与补条目。
- 版本不一致时 `check:orchestration` 判错。

### S7 基线只减不增

- 先跑 `npm run check:zh`，取当前违规数。
- 改基线 MUST 在台账 `reason` 列写 `baseline:<N>`。
- 自检按台账最近一条 `baseline:<N>` 比对。
- 当前基线值大于该数即判错。
- 基线只能下降。上升 MUST 先写理由与复核记录。
- 判定细节见 `specs/002-content-orchestration/contracts/check-contract.md` §3。

本技能正文 MUST 纳入 `check:zh` 范围。

## 优先级与变更日志

冲突时按下列顺序裁决。

1. 宪法：`.specify/memory/constitution.md`。
2. 内容契约：`specs/001-docs-engine/contracts/content-contract.md`。
3. 本技能。

- 与宪法冲突时以宪法为准。
- 与内容契约冲突时以契约为准。
- 契约与技能冲突时 MUST 开任务改技能。
- MUST NOT 两处各改一半。
- 技能自身改动 MUST 记进变更日志。
- 条目含日期、改动与原因三要素。
- 变更日志见 `.dsh/skills/docs-authoring/CHANGELOG.md`。
- 编排判据见 `specs/002-content-orchestration/contracts/skill-contract.md`。
