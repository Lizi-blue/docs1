# docs-1 Constitution

## Core Principles

### I. 内容即事实源，导航是派生视图（NON-NEGOTIABLE）

`docs/**` 下的 Markdown 与 YAML 元数据是唯一内容事实源。导航、侧边栏、入口索引、学习路径、
关联链接、搜索索引 MUST 由引擎从事实源派生，MUST NOT 手工维护。

- 页面间引用 MUST 指向已存在的目标。未建的页面用行内代码标注，MUST NOT 写死占位链接。
- 同一事实 MUST 只有一处正文。其余位置只放指针与一句话结论。
- 引擎代码、schema、脚手架与技能文档 MUST NOT 各自复述同一份取值。

理由：手工维护的导航在十余个页面时可行，在上千个页面时必然漂移。事实一旦有两处，
读者就再也无法判断哪处为准。

### II. 零配置扩展（NON-NEGOTIABLE）

新增领域、知识域、知识点或组件 MUST 只需新建目录与文件。引擎代码与站点配置 MUST NOT
需要改动。每个领域根目录 MUST 提供渐进式学习与组件查询两个入口。

- 领域与知识域的名称、图标、顺序、描述 MUST 来自目录级 `_meta.yml`。
- 页面的类型、层级、标签、依赖 MUST 来自 frontmatter，缺省时 MUST 有安全默认值与可定位告警。
- 零配置扩展 MUST 有机械证明：在隔离样本上断言导航与页面出现，且配置改动数为零。

理由：扩展能力靠口头承诺会退化。只有可执行的断言才能证明「加目录就行」。

### III. 内容契约可执行（NON-NEGOTIABLE）

目录层级、命名、元数据与页面结构 MUST 有机器可读约束，并配套机械校验与新建脚手架。

- schema、校验脚本、脚手架与创作技能 MUST 同源，或统一指向规范正文。
- 校验 MUST 覆盖元数据合法性、必需小节、命名与数字前缀、内部链接与图解产物存在性。
- 校验 MUST 在 CI 中 fail-closed 执行。存量不合规内容走基线，基线只减不增。
- 新增内容 MUST 由脚手架或规范模板产生，作者只填正文与取值。

理由：规范写进文档只约束认真读的人，写进脚本才约束所有人。

### IV. 受控中文与机械门禁（NON-NEGOTIABLE）

中文正文 MUST 遵守受控中文规则。规则正文以上游 `lemonhall/asd-ste100-skill-zh` 为准，
本仓以 vendored 脚本 `scripts/ste-lint-zh.py` 机械判定。

- 一句一动作。说明句 MUST NOT 超过 40 字，指令句 MUST NOT 超过 25 字。
- 主动语态，明确执行主体。同一概念全篇同一个词。
- MUST NOT 使用虚动词（进行、加以加名词）、套话、营销形容词与含糊词。
- MUST NOT 用分号连接多个动作。MUST NOT 改动情态词的置信度。
- 本仓 MUST NOT 自造与上游同义的规则，MUST NOT 放宽上游阈值来迁就存量文本。
- 代码块、命令、专有名词与 API 名称 MUST 走脚本豁免机制，MUST NOT 靠人工忽略。
- 局部停用规则 MUST 走 `--disable` 显式清单，并在提交信息里写明理由。
  在文件里写忽略标记绕过门禁 MUST NOT 被接受。
- 中文检查 MUST 作为流水线中的显式阶段运行，MUST NOT 静默跳过。

理由：风格靠记忆必然漂移。机械规则是唯一可持续的约束，也是新增内容的统一门槛。
规则一旦允许本地变体，门禁就失去可比性。

### V. 图解自包含且可重建

原理、流程、时序、状态机与依赖关系图解 MUST 以自包含交互 HTML 交付，由 Archify 生成。

- 图解 MUST 支持离线交互，MUST NOT 依赖外部 CDN 或在线服务。
- 可编辑源描述（JSON IR）与生成命令 MUST 入库，产物 MUST 入库。
- CI MUST NOT 依赖外网生成图解，只校验产物存在与自包含性。
- 单页至少一个图解。图解缺失时 MUST 构建告警并显示占位，MUST NOT 留空白区域。
- 图型 MUST 按「这张图要回答什么问题」选择：组件与边界用 architecture，调用顺序用 sequence，
  数据流向用 dataflow，状态流转用 lifecycle，步骤与审批用 workflow。
  图注 MUST 写明该图回答的问题。
- 图 MUST 出现在 `## 原理图解` 或 `### 数据流图解` 之内服务讲解，
  MUST NOT 作为装饰散落正文，MUST NOT 用两张图回答同一个问题。
- 云架构与拓扑静态图 MUST 用 `mingrammer/diagrams` 的 `.py` 源生成，构建前执行，产物入库。
  MUST NOT 用它替代 Archify 的交互图。
- MUST NOT 引入第三个图库或以 Mermaid 替代上述两类产物。

理由：教程的价值有一半在图上。图不可重建，内容就无法长期维护。
图不服务讲解，读者就只是多看了一张装饰图。

### VI. 组件按生产级交付

组件页 MUST 呈现可直接搬运到其他项目的资产，而不是代码片段集合。

- 组件 MUST 具备完整源码、设计说明、使用文档、接口说明与自动化测试。
- 组件测试 MUST 在 CI 中执行，失败 MUST 判红。
- 组件 MUST NOT 依赖本仓私有资源或未公开约定。
- 发布为可安装包为可选能力。未发布时，引用方式 MUST 给出等价的源码引入做法。
- 组件与知识点 MUST 双向可达：知识点页显示被哪些组件复用，组件页显示依赖哪些知识点。

理由：面试备考的终点是可复用产出。不能运行的组件无法证明讲解正确。

### VII. 规模优先

任何设计取舍 MUST 先回答「内容涨到上千页面时是否仍然成立」。

- 目录层级最多四层，侧边栏可见层级不超过三层，深层默认折叠。
- 侧边栏 MUST 按当前领域或知识域作用域渲染。站点 MUST 提供全站搜索与面包屑。
- 内容作者新增一个知识点的操作步骤 MUST NOT 超过三步。
- 构建时长与导航数据体积 MUST 有预算上限，超出时 MUST 告警，MUST NOT 静默退化。

理由：本仓的目标形态是几十个领域、上千个页面。小规模下好用的方案在大规模下会失效。

### VIII. 教学编排持续改进（NON-NEGOTIABLE）

内容编排与教学法 MUST 沉淀为一份可演进的技能。领域怎么划、路径怎么排、每讲怎么讲，
MUST 有统一判据，MUST NOT 只停留在各页经验里。

- 仓内 MUST 有一份可被 Agent 直接加载的「内容编排」技能，位置为
  `.dsh/skills/docs-authoring/SKILL.md`（或等价项目技能目录）。
- 每个领域与知识域 MUST 在该技能登记：目标读者、先修、学完能做什么、路径分段、每讲教学目标。
- 每讲 MUST 给出四个教学要素：本讲要解决的问题、常见误区、面试追问链、与下一讲的衔接。
- 每次内容迭代 MUST 判定是否需要回写该技能，并留下判定记录：回写，或声明「本次无需回写」。
  连续三次声明无需回写时，评审 MUST 复核编排判据是否已过时。
- 该技能 MUST 有变更日志，逐条记录日期、改动内容与原因。
- 该技能 MUST 只指向规范正文（`contracts/content-contract.md`），MUST NOT 复制取值。
- 技能的演进 MUST NOT 削弱本宪法其它条款。与宪法冲突时，以宪法为准。

理由：教学效果靠复盘积累。技能不更新，新增内容只会重复旧的讲法，
上千页之后就没有统一的教学节奏可循。

## 技术约束与交付约束

- 渲染层固定为 VitePress 加 Vue 3。理由：它本质是 Vite 应用，解析层能深度介入构建流程。
  MUST NOT 改用无法定制解析流程的静态站点生成器。
- 解析层 MUST 由 Vite 插件与 VitePress 数据加载器组成，产出虚拟模块与扁平页面索引。
- 路由 MUST 由解析层决定：源文件带数字前缀（排序用），URL 去掉前缀（读者用）。
  路由重写表 MUST 由同一份页面模型生成。
- 站点 MUST 为静态产物加静态服务器：无后端进程、无数据库、无持久卷。
- 部署 MUST 复用 `ci` 中心仓流水线：仓内只保留薄触发工作流、`ci.env` 开关文件、
  Dockerfile 与业务自带清单。MUST NOT 复制中心仓的编排与平台供给实现。
- 部署目标为 Kubernetes 命名空间 `docs` 与域名 `docs1.minilab.uzibird.cn`，入口走 HTTPS。
- 域名解析与证书是外部前置，MUST 在文档中显式记录责任方与验证方式。

三类内容工具的分工唯一如下，MUST NOT 越位：

| 工具 | 定位 | 来源与入库方式 | 禁止项 |
|---|---|---|---|
| `asd-ste100-skill-zh` | 中文写作规则的唯一正文 | vendored `scripts/ste-lint-zh.py` 逐字节入库 | 自造同义规则、放宽阈值、文件级忽略标记 |
| Archify | 交互图解的唯一来源 | JSON IR 入 `diagrams/src/`，HTML 产物入 `docs/public/diagrams/`，`scripts/gen-diagrams.sh` 重建 | 联网生成、用其它交互图库替代 |
| `mingrammer/diagrams` | 云架构与拓扑静态图的唯一来源 | `.py` 源入库，构建前生成 PNG 入库 | 替代交互图，或在无云架构专题时提前引入 |

- 内容编排技能 MUST 保持两处形态：仓内一份供 Agent 加载，`dev/skill` 一份供跨仓复用。
  两处 MUST 只放判据与指针，取值只在 `contracts/content-contract.md`。

## 开发流程与质量门禁

- 提交前 MUST 通过单一门禁入口，且退出码为 0：
  `npm run check:content` 加 `npm run check:zh` 加 `npm run build`。
- 内容改动与引擎改动 MUST 分开提交。引擎改动 MUST 附一条零配置扩展的验证记录。
- 内容类提交的完成定义 MUST 包含：四段式完整、四个教学要素齐备、图解合规（图型与图注）、
  中文门禁通过、编排技能判定记录。
- 图型选择 MUST 在提交说明里可见：选了什么类型、这张图回答什么问题。
- 规范升级 MUST 输出不合规清单，并更新基线；基线 MUST 只减不增。
- 流水线阶段 MUST 显式，失败 MUST 可定位到阶段与首个原因。MUST NOT 有静默跳过。
- 每个特性的规格、计划与任务 MUST 声明其遵守本宪法哪些原则。冲突时以本宪法为准。
- 提交信息使用中文，并带特性编号，例如 `spec(001-docs-engine): …`。

## Governance

本宪法优先于其他开发实践与文档约定。与之冲突的约定 MUST 修改或废止。

- 修订流程：提出修订 → 在宪法文件头部写 Sync Impact Report → 升级版本号与日期 →
  更新受影响的原则与章节 → 人工评审通过后提交。提交前 MUST 移除 Sync Impact Report。
- 版本策略：语义化版本。原则的删除或重定义升 MAJOR；新增原则或实质扩写升 MINOR；
  措辞澄清与错别字修正升 PATCH。
- 合规审查：每个特性的规格与任务 MUST 逐条对照本宪法；门禁脚本是机械判据，
  人工评审是补充判据。两者冲突时，MUST 先修脚本或先改宪法，MUST NOT 两边各改一半。
- 技能与规范一致性：每次技能变更后 MUST 校验技能内无重复取值，只允许指针。
  技能版本与本宪法版本解耦。技能条款 MUST NOT 覆盖或削弱本宪法条款。
- 豁免：任何豁免 MUST 写在特性任务里，并给出恢复计划。豁免 MUST NOT 扩散，
  且 MUST NOT 用于跳过受控中文、内容契约与组件测试三类门禁。
